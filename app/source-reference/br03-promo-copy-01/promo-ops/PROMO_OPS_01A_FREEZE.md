# PROMO-OPS-01A｜门店仓位促销标签体系、库存紧迫感规则与全链路露出矩阵冻结

- 项目：迷你考拉仓微信小程序
- 版本：V1.0 / 2026-10-26
- 状态：**产品演示阶段规则设计冻结**；既有批准规则继续有效；视觉签收、真实原型归并与生产上线均未发生。
- 范围：H01/S01/S02/S5/快捷下单/预约留资/O01；U01不作为最新主链必经页面。

## 1. 总体冻结原则

1. 一套促销事实源：按门店、仓位、容量组、有效租期、用户资格、活动时限决定展示。
2. 四类信息：价格活动、真实库存、服务权益、门店事实。库存数量与活动名额不得混用。
3. 一张仓位卡最多1个主促销标签 + 1条库存提示 + 1条优惠金额或服务权益说明；严格避免促销横幅、动画干扰报价和CTA。
4. 没有对应事实时不展示营销信息；不得随机分配免押金/大促标签，不采用虚假浏览人数和循环倒计时。
5. 已确认租期的整期总租金为主价，月均约为辅；未确认租期只能显示参考价格；订单本次应付与租金明确区分。
6. 活动优惠、常规租期折扣、优惠券、服务权益分别计价，进入O01沿用同一有效Quote/Price Snapshot。
7. 本轮不新建营销页，不修改中央原型，不覆盖四分支批准视觉，不擅自改推荐排序和交易链。

## 2. 最新用户链路

- A：H01→S01→S02→O01；S01仓位预览不得新增直接下单按钮。
- B：CAP/ITEM/AI/ADVISOR→S5→O01，或S5→S02→O01。
- C：H01「预约订单」→快捷下单→O01；预约用仓仅生成销售线索，不创建正式订单。
- 历史U01上库存紧迫感与促销事实迁移到S02/S5/O01相应的决策位置，而非恢复U01页面。

## 3. 标签标准

详见 `PROMO_LABEL_DICTIONARY_V1.csv`。核心用户文案：

- 促销：`特价仓`、`限时特惠`、`新客专享`、`长租优惠`、`整期省¥X`、`指定仓型特惠`。
- 库存：`同容量仅剩这1个`、`同容量仅剩2个`、`同容量剩余X个`、`匹配仓位仅剩X个`、`匹配仓位X个`。
- 状态：`已售出`（仓位）、`已售罄`（整店）、`暂无符合需求的仓位`（有仓但不匹配）。
- 权益：`送单程基础运输`（资格确认）、`可享运输优惠`（有条件待最终确认）、`新客券已抵扣¥X`（已应用）。

所谓`特价仓`必须有仓位级别的明确活动资格，不能因为页面排名第二就自动显示；`整期省¥X`必须有同仓、同租期、同范围的真实价格基准并说明比较对象。

## 4. 冻结库存规则

| 场景 | 条件 | 文案 | 特别限制 |
|---|---|---|---|
| S01 有需求 | 匹配数=1或2 | 匹配仓位仅剩X个 | 需求容量及必要约束先确认 |
| S01 有需求 | 匹配数>2 | 匹配仓位X个 | 不强制使用紧张颜色 |
| S01 无需求 | 无匹配数量含义 | 不出现匹配稀缺 | 可以呈现正常库存事实 |
| S02 同容量=1 | 可租数1 | 同容量仅剩这1个 | 同容量分组要明确 |
| S02 同容量=2 | 可租数2 | 同容量仅剩2个 | 不虚构竞争用户 |
| S02 同容量3–5 | 可租数3–5 | 同容量剩余X个 | 普通提醒 |
| S02 同容量>5 | 可租数超过5 | 可不展示稀缺信息 | 不人为制造紧迫 |
| 整店无库存 | 可租数0 | 已售罄 | 不参加正常可购推荐 |
| 有库存无匹配 | 匹配数0 | 暂无符合需求的仓位 | 不能说已售罄 |

用户应看见真实对应的供应稀缺，而不是夸大危机。演示中可用稳定模拟数据验证UI，但对客模式不能使用伪造的`X人正在查看`或无限重置倒计时。

## 5. 活动名额与仓位数分别核算

- `available_same_capacity_count`: 同仓型/容量组可租数。
- `matched_available_count`: 当前需求下满足条件的可租仓位数，去重。
- `store_available_unit_count`: 门店总可租仓位数。
- `campaign_remaining_quota`: 活动核销名额余额，只用于确有名额上限的活动。
- 活动名额不得由仓位数量推断；仅剩1个仓也不意味着限时优惠只剩1份。

## 6. 页面露出矩阵

详见 `PROMO_PAGE_EXPOSURE_MATRIX_V1.csv`。核心规则：

| 页面 | 推荐展示 | 不允许 |
|---|---|---|
| H01 | 三店推荐原序不变；第3张可呈现1个运营理由；参考单价 | 不新增全屏抢购层、不用未选租期的确定价 |
| S01 | 门店属性与指定活动区分；有需求显示匹配紧张；仓位预览简明 | 不加仓位预览直接下单，不展示虚假匹配数 |
| S02 | 具体容量、整期报价、一个促销标签、同容量库存、立即下单 | 不恢复旧U01、不过量堆叠标签 |
| S5 | 匹配仓位的整期租金、折扣/优惠、库存事实；可直达O01 | 不能因折扣伪称总支出更少 |
| 快捷下单 | 只显示有效选择的仓位/报价促销 | 无仓位/租期不生成可支付有效价 |
| 预约用仓 | 有条件的营销提示、售前解释 | 不把线索认作订单或锁仓 |
| O01 | 有效报价快照内的优惠后租金、抵扣、押金、管理费、首次应付 | 不继续追加抢购角标、不静默修改券/报价 |

S01双店展开属于独立视觉候选：当前排序前2默认展开，每店最多2条仓位预览；第三家及之后可折叠。它不代表已经修改批准的S01视觉母版。

## 7. 推荐、价格、券与运输规则

- H01三推荐位保持：1最近，2稍远更省，3运营促销；无依据不显示`3km内最低`等标签。
- S01的正常排序不因促销标签本身而自动重排；运营位需有明确位置定义。
- 旧价格阶梯与整期取整算法继续服从Price Semantics V1.1，当前PROMO规则不另立折扣算法。
- 现金租金券只减少租金，不减少押金和管理费；管理费维持既有¥50演示口径；押金基数保持当前既有Quote逻辑并列为财务待核。
- 新签首单运输活动的既有条件为租期≥6个月、距离≥5km、成交折扣比例≥0.6且资格核实；未确认不显示已赠送。
- 不能假定所有新用户都有¥200券，实际申请、领取、可用和抵扣状态必须区分。
- 价格变化、活动失效、库存改变、券资格变化时，旧报价不得静默进入支付。

## 8. 信息优先级与视觉约束

决策顺序：不可售/无匹配守卫→有效报价→促销资格→选择一个主促销→选择真实库存提示→展示次级权益与门店属性。

- 主促销标签：浅橙底、深橙字，遵守分支已批准的色彩与信息架构，不新造渐变/贴纸。
- 库存信息：一行文字为主，不再叠加同义徽章。
- 普通门店卖点：中性低权重，必要时在窄屏隐藏最末项，不裁切关键价或CTA。
- 任何可见业务文字原则上不低于12px；375×812和390×844双尺寸试装。
- 不因营销需求改造已批准卡片容器，不增加卡中卡与大片深绿色。

## 9. 促销事实最小字段

| 字段组 | 字段建议 | 职责 |
|---|---|---|
| 仓位 | `store_id, unit_id, size_group_id, available` | 唯一身份和可售状态 |
| 需求 | `required_capacity, term_months, demand_constraints` | 判定匹配 |
| 活动 | `campaign_id, campaign_type, unit_ids, eligible_terms, start_at, end_at, eligibility, quota` | 判定活动资格 |
| 价格 | `quote_id, price_version, total_rent, monthly_average, coupon_applied, coupon_amount, payable` | 唯一价源 |
| 展示 | `primary_promo_id, inventory_text_id, benefit_id, evidence_type` | 控制前端文案 |
| 状态 | `quote_valid, inventory_valid, campaign_valid` | 失效需重确认 |

演示数据应标明`presentation_fixture`并与可上线事实源隔离；它用于UI测试，不构成真实承诺。

## 10. 冲突与降级决策

1. `已售罄/已售出` 优先于任何优惠显示；不能让禁用仓位继续出现`立即下单`。
2. `NO_MATCH` 优先于`库存紧张`，不可把无匹配显示为供给售罄。
3. 无有效租期不生成正式整期租金和省钱金额。
4. 无真实活动期限/额度不出现`限时`/`剩余名额`；没有真实浏览指标不显示`X人正在看`。
5. 同一仓位多促销同时满足：选择对用户当前报价真正适用、价值明确、优先级最高的1个主标签；其他优惠在适当页面的费用说明呈现。
6. 运输服务资格、租金现金券、普通租期折扣与专项特价分别核算，不能叠加重复减价。
7. 数据冲突时优先隐藏不能证实的促销字段，而不是猜测或沿用旧页面字符串。
