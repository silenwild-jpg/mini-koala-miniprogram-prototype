# Mini Koala — 大容量需求与组合仓位推荐策略 V1 / 第一阶段受控实现

日期：2026-10-12  
状态：候选版本；Release Gate **HOLD**；本阶段未实现多仓自助在线下单

## 一、需求与边界

1. S01 门店卡标签使用完整池：`近地铁／新开门店／双11大促／24小时／电梯直达／热门／仓型齐全／免押金`。每家门店按门店 ID 生成稳定的 2–4 项随机标签，单行滚动，不出现“演示”提示，也不按标签内容过滤；标签与真实押金、活动资格、服务承诺**不联动**。
2. 已知容量/物品估算后，匹配先评估本店可用单仓；单仓不可满足时，在同店检索 2 或 3 间的组合。推荐卡首选 2 间；无 2 间时才展示 3 间。最多展示两种组合。
3. 只有组合**容量合计不小于当前目标容量**，且每个选中仓型可租数量充足，才标为“组合可满足”。不重复消费只有一个库存的仓位。组合不是实际仓位锁定。需核对大件单件尺寸，不能据容量合计推断长件一定装得下。
4. 组合整期租金按各仓型的**现行折扣、所选租期和门店倍率分别计价，再求和**；月均仅为整期租金除租期后的参考显示。押金、管理费组合收取规则待确认，第一阶段不进入 O01 支付，不隐含费用承诺。
5. S5 识别同店单仓/组合/相近方案，S01（携带需求）区分“匹配仓位”与“可选组合”；S5 和 S01 均进入携带需求的 S02 门店详情，不恢复 S9 门店仓位列表页。
6. S02 组合卡显示仓间数、各间容量、总容量、整期租金和月均租金；动作“咨询此组合”传递店铺、租期、需求和各仓型明细，继续由现有顾问入口承接。若单仓和组合均不足，展示“查看附近可选门店”直接跳转 S01 保留需求、位置和租期；既有售罄兜底沿用原状态。
7. 现有 U01 单仓详情、订单、支付、租后生命周期不变。完整多仓订单、押金/管理费、多仓续租/退租及真实库存预占明确为第二阶段研究项。此包不得用于生产直接发布。

## 二、规则优先级

- 同店单仓容量命中现有需求区间且有可租库存 → 正常单仓链路。
- 否则组合：先两仓，再三仓；同间数优先容量冗余少、整期租金低。
- 同店全不可满足 → S01 附近可选门店（携带原容量、租期、定位、行程方式），若仍无满足项则保留顾问/相近方案。
- 单间的最长边/门宽等尺寸限制与组合总容量分开判断，存在大件标记时提示需要核对；当前真实尺寸不足以作承诺。

## 三、交互与异常状态

| 状态 | S5/S01 | S02 | 后续 |
|---|---|---|---|
| 有单间仓符合范围 | 单仓需求匹配、正常整期价 | 常规匹配仓卡 | U01 单仓详情 |
| 无单仓，有两仓 | 组合可满足、2 间/合计容量 | 展示同店组合、整期合计租金 | 顾问协助确认组合 |
| 无两仓，有三仓 | 组合可满足、3 间/合计容量 | 展示同店组合、整期合计租金 | 顾问协助确认组合 |
| 本店组合亦不能满足 | 本店显示相近空间，不伪称匹配 | 附近其他门店兜底入口 | S01 继续比较 |
| 只有 1 间相同容量剩余 | 不允许重复计数 | 不输出伪两仓方案 | 附近兜底 |
| 全店售罄 | 不输出可租组合 | 沿用售罄恢复路径 | S01 查看其他门店 |

- 组合匹配器 Node 隔离测试覆盖单仓优先、两仓、三仓、同容量数量校验、售罄排除、租金求和、大件复核标识。
- 375×812/390×844 采用 Chromium **离线资源注入**验证 S02 组合/无组合状态，包含 JS 执行。此方法显示页面而不依赖受限的本地 HTTP，截图为布局证据；它**不是**完整本地 URL/微信真机跨页点击验收。
- 当前 Chromium 对 `http://127.0.0.1:*` 返回 `ERR_BLOCKED_BY_ADMINISTRATOR`，离线 about:blank 环境含个别使用绝对 URL 的初始化错误，不将其当作正式链路通过。
- 第二阶段必须明确组合订单模型、仓号实际分配/锁仓、押金与管理费、退款/开票/续租退租归属、完整最短边和大件约束。
