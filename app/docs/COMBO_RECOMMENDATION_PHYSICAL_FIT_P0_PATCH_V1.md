# Mini Koala — Combo Recommendation / Physical Fit P0 PATCH V1

日期：2026-10-12  
基线：`Mini_Koala_Combo_Recommendation_V1_Candidate.zip`（内容哈希经当前容器比对）  
状态：**内部演示候选；Release Gate HOLD**。未接入实测长宽高、门洞、通道或真实库存锁定，亦未开放多仓在线下单。

## 1. 此次解决的问题

上版组合算法仅用总立方数判断“组合可满足”。本轮对单件物品（不得跨仓拆分）、每个仓位的实际测量证据、逐间容量预算以及顾问承接链路增加安全门禁。当前仓型母表 `766/766` 条尺寸均系体积换算模拟：这些仓只能显示“容量候选／物品尺寸待核对”，**不能给出实物适配确认**。

## 2. 执行规则

1. 新增共享 `mini_koala_physical_fit_v1.js`，通过 `constraintsFromSelection` 保存物品 ID、名称、所选规格、数量、单件估算体积、已知尺寸、尺寸来源与高风险提示；扩展衣柜、冰箱、托盘、文件柜、桌柜等尺寸敏感物品。标准纸箱 60×40×50cm 仍标为**预设估计**，并非实测尺寸。
2. 当 **物品三维尺寸** 和 **仓内净尺寸** 均来自可验证测量，且任何仓都不能容纳该不可拆分物品时，组合标记 `rejected`，不进入主推荐。门洞约束若也有可信尺寸，则参与单件入口判断；模拟门洞不得用于通过证明。
3. 当总物品估算体积大于组合名义体积，直接排除；否则通过有界回溯做分仓体积分配，保留每间物品建议。该算法仅检验容量预算，**不是完整 3D 装箱与通道可用性证明**：分仓未知、搜索超限、仓体/门洞/物品尺寸未知时状态 `pending`。启发式无解不等于物理上绝对无解，因此不以搜索失败单独给出硬拒绝。
4. `verified` 仅可由实测仓体净尺寸、实测门洞、有效物品尺寸、容量分配且另有人工核验摆放方案共同构成；正式母表尚不满足。当前页面不依据模拟尺寸升级状态。
5. 同店单仓满足容量但已经被可靠的单件尺寸证伪时，不再阻断组合搜索；仍然按照既有两仓、三仓和可租数量规则搜索。组合无可行候选时，S02 保留原有附近门店兜底。
6. S5、S01、S02 统一将无适配证据的方案称为“容量候选／尺寸待核对”，移除过度确定的“组合可满足”。S02 仅展示有可解释体积分仓分配的拟放物品，否则提示“分仓摆放与门洞尺寸待核对”。顾问咨询记录新增 `fit_status`、`fit_reason_codes`、`fit_allocations`、`item_constraints`、`item_summary`。已留手机号二次咨询仍更新最新本次需求并给出反馈。
7. 既有 U01/O01 单仓交易、押金、管理费、库存母表及标签池保持不变。不会向多仓订单/支付跳转。

## 3. 边界与重要限制

- 仓型 `dimension_estimate_status=simulated_from_volume_square_floor`，门洞 `door_estimate_status=simulated_from_volume`：不可当作实测；因此当前业务数据不产生“已适配”的商品承诺。
- 物品尺寸仅标准箱有显式目录预设尺寸；沙发/床/家具等大件缺少完整三维尺寸，默认 `unknown`，不会虚构物品长宽高。品类高风险标签不是实测证据。
- 逐仓体积分配不是几何摆放证明。实际能否通过门洞、转弯、使用电梯及保留取物通道仍需门店/顾问确认。面积利用率、可堆叠、货物重量与承重本轮没有真实数据，不作自动放行判断。
- 人工构造且 **可信的尺寸测试夹具** 可以证明不可拆分 3.5m 物品不能进入净空间最大边小于该尺寸的仓位；此结论不能映射为“现有某真实门店已证实不能存放”。
- `staffValidatedLayout` 仅为未来审签接口，当前页面不传入，任何源自模拟仓型的推荐不得升级为 `verified`。
- 当前演示中的仓位依然不是后端预占仓号；实物适配与库存锁定均须上线前接入事实数据。
