# 估算工具分类、预设和结果口径 PATCH V1

基于 `ESTIMATOR_P0_PROTOTYPE_VALIDATION_V1.md`，继续修复已能由当前原型确定的内部矛盾；保留冻结 HTML 页面，通过同一估算补充脚本生效。

## 已修改

1. **物品顺序**：将当前数量大于 0 的场景物品提到“已选物品 · 核对数量”，原先位于首屏但数量为 0 的物品移入“可能还要加”。已选的“更多物品”不再藏在折叠区域。原按钮与数量事件保持绑定。
2. **全库类别**：全库 40 项各归入家具、家电设备、箱包与收纳、收藏与长件、商家与办公物资之一；关键词搜索仍可跨全部类别。类别只用于浏览，不限制场景内可添加的物品。
3. **已知预设矛盾**：行李“2–4个箱包”默认从 5 件调至 4 件；“单间／合租搬家”的默认说明改为纸箱、行李和收纳箱；企业“文件档案”不再默认预填打印机。
4. **档位与结果同源**：每个数量档位所示空间范围从当前预设、规格和既有 `calc()` 算出；进入租期页时首屏保留 `calc().target`，不先按 0.5m³ 四舍五入。用户主动点击容量加减时仍以 0.5m³ 调整，目标值展示到 0.1m³。
5. **数字含义**：物品行区分“单件参考体积”与“当前合计体积”；自定义条目注明“按填写尺寸”。结果处说明已计入常见摆放余量，并提醒长件仍需核对门宽和通道。零数量物品不展示“当前约 0.00m³”。

## 仍需事实校准

单件体积假设和场景摆放效率（0.70–0.90）、默认余量系数（1.15）没有逐项实测证据。此次仅消除跨步骤不一致与明确文案错误，不能据此宣称实体仓位、搬运通道或储存条件已精确匹配。下一步应采集典型物品的**收纳后长宽高、能否拆叠、最长边、来源与样本数**，再校准数量档位和推荐区间；托盘需区分空托盘与承载货物后的外廓。
