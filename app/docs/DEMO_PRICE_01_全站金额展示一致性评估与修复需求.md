# DEMO-PRICE-01｜全站金额结构、价格语义和视觉强弱层级一致性：评估与修复需求

日期：2026-10-14｜状态：需求冻结/源码初查；待浏览器复测；严禁未经授权全站覆盖

## 1. 核心问题与目标
全站必须通过**金额是什么、适用什么租期、是否可成交、哪些费用包含/不包含**让用户一眼理解，而不只是把所有数字用橙色放大。只调整显示语义、排版和视觉权重，不改SSOT、计算/折扣/支付、优惠资格或快照。现行《PRICE_SEMANTICS_DISPLAY_SPEC_V1》与《Visual V3 V1.1.1》为基准。

## 2. 四级金额系统（排他性的同一区块主视觉）
| 层级 | 语义 | 典型显示 | 视觉约束 |
|---|---|---|---|
| L0 发现价（未选租期） | 非成交参考 | `¥88 /月/m³ 起` + `参考单价` | 20–28px，必须有单位，不出现整期成交暗示；服务于比价 |
| L1 整期方案价 | 已有有效租期的可租仓位/方案 | `6个月 · 整期总租金` / `¥3,440` / `月均约¥573/月` | 主金额26–32px/橙，月均11–13px灰；起价只有多个适用仓位最低价时展示，不错用 `/起` |
| L2 租仓交易应付 | 下单前确认费用 | `预计下单一次支付 ¥3,863`（依据已有快照示例，不是默认价格） | 同一支付区块唯一主金额28–32px/橙；明细列租金、券、押金、管理费，右对齐 |
| L3 已支付/退费/余额 | 支付后事实/售后 | `已支付` / `押金待退` / `退款金额` | 优先展示状态与金额关系；不得继续用“预计应付”表达已完成支付 |

**规则**：L0与L1不得混写；同一卡片只允许一个橙色主金额。折扣/节省归第三层，不得与总价同尺寸/同颜色；不可用/参考/起价要有文字说明。中文金额千分位、`¥`、单位、租期标注需一致，月均必须由SSOT得到；押金等不能从整期租金卡偷换为月租。
