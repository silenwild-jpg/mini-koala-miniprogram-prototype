# C-State P1 + D-Page Cleanup

## 阶段定义来源

本轮按“模型使用建议”聊天中对下一阶段的定义收口，不重做此前已统一的共享规则：

- M01 正常在租状态标题改为“当前服务”；只有真实待办继续使用“待处理事项”。
- M01“老友记”推荐卡降为紧凑、低视觉权重入口，并保留在当前服务之后。
- S01 清除“照片区域”实现占位词，改为中性门店环境区域。
- S02 压缩并中性化图片占位；HIGHVALUE 状态只保留一组主说明和一个主行动，顾问入口为次级行动。
- U01 未接入真实照片前不再使用“实拍”表述，统一为仓位入口/环境示意。

## C-State P1

- 前端可选集合只包含 `display_price_min > 0` 且 `has_zero_price=false` 的容量档位。
- 门店没有任何可展示容量档位时，不进入门店列表。
- 门店可租数量、容量范围和最低价均从过滤后的可展示档位重新汇总。
- 源数据仍保留在生成前输入和校验统计中，前端页面不自行复制或过滤事实。

本轮过滤结果：271 个零价相关容量档位、282 个仓位不展示；前端保留 126 家门店、766 个容量档位、1,297 个可租仓位。

## D-Page Cleanup

- Estimator、S01、S02、U01 与 H01 统一使用生成数据源。
- 容量统一显示为 m³。
- ㎡使用 `m³ ÷ 2.5m` 换算；长、宽按等边地面面积推导，高度统一为 2.5m，页面不额外标注“模拟”。
- 生成数据保留尺寸估算状态；真实长、宽、高补充后由数据源统一替换。门宽和空间形态仍保持待补充状态。
- 清除固定 8 个仓位、固定容量范围和 U01 固定仓位字典。
- HIGHVALUE 推荐仓位从当前门店过滤后的真实可租档位动态计算，不再使用固定 7.8/12m³ 演示容量。

## 验证边界

本轮为静态数据与页面清理。当前长宽高是由容量和 2.5m 层高推导的原型值，不代表真实测量；不包含真实门宽测量、线上库存、地图和交易接口验证。
