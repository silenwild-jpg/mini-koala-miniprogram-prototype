# Phase 2 PATCH V1 修改与验证说明

本轮将五项修正规格落实到独立原型候选版。尚未发布，HOLD。

|项目|改动后的用户行为|
|---|---|
|地址联动|选择受支持的演示位置后，同步更新匹配位置、距离、推荐和后续页面；取消不更改。原来源页面上下文保留。|
|容量调整|结果区、底栏和容量加减入口统一打开编辑；确认后生效，取消保留原值。物品清单、租期和位置不清空。小于原估算时提示用户确认。|
|E存承接|可查看服务方式和需求摘要，主动咨询后复用联系信息流程；只保存演示记录，明确未发送给真实顾问。取消不提交。|
|推荐理由|只有实际整期租金较低才写更省，同价/更高写另一家匹配门店。列表标签按真实最近方案比较，不依赖显示顺序。起价比较说明同需求范围，备选不显示省钱结论。|
|筛选继承|估算完成保留主动选择的排序、距离和服务；已关联需求也实际执行距离筛选。取消恢复原列表上下文，完成从顶部显示新结果。无结果由用户主动调整，不自动放宽。|

本轮还修正列表在普通浏览状态选择价格排序后没有实际按价格排序的问题，保留北京优先的默认距离浏览。已关联需求价格排序说明为整期租金，普通浏览说明为每月每立方米单价。

## 验证范围

- 68 个既有静态与模拟运行检查。
- 新增 18 组行为检查：编辑/取消/确认、价格高低、地址上下文、E存主动提交与演示反馈等。
- 在真实S01页面脚本的模拟环境中验证已关联需求距离过滤、服务过滤以及无结果时不自动放宽。
- 原有状态、定价、按钮状态、底栏几何约束、交易与生命周期相关回归；本地HTTP路径检查及打包完整性检查。

这些验证不是浏览器端到端或微信真机验收。规格中的28条验收场景没有全部通过：截图/视觉、微信原生返回、软键盘、真实授权、付款保证理解等仍待执行。

## 检查基准调整

旧测试中固定“弹窗改地址”“E存未开发提示”“完成后取消距离筛选”“强制推荐排序”的断言已更新为本次规格。原型新增共享模块后，模拟运行测试同步加载该依赖。

只更新本轮有意修改的两张页面的完整文件/正文哈希保护；其他页面继续保留原检查。记录见 PHASE2_APPROVED_DELTA_HASHES.json。原母版及原测试未修改。
