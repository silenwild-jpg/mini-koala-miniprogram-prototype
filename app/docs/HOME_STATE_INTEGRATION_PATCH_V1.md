# Mini Koala — Homepage State Integration PATCH V1

日期：2026-10-12　性质：内部演示候选版　Release Gate：**HOLD**

## 1. 本次母版与边界

源自 `Mini_Koala_Combo_Physical_Fit_P0_PATCH_V1_Candidate.zip`。仅修改 H01 页面状态呈现、普通首页门店卡浏览行为、以及配套样式；不重构估算、S01/S02、U01、订单、生命周期、组合仓位与价格逻辑。完整保留已有业务链、展示文案以及新用户首页的主要模块顺序。仓型物理尺寸、包装/拆装尺寸仍作为后续开发数据，不在本轮推断。

## 2. 代码修改

- 原先的 `setState()` 会将 `.state-new` 区块一并隐藏，使首屏主标题、双任务、三张推荐、场景、四步流程及品牌证据从已估算/预约/报价/支付/用仓首页消失。本轮调整为通用首页对所有非 B2B 特殊演示状态持续可见。
- 复用现有 `pendingCard`、`viewingCard`、`estimatedCard`、`quotedCard`、`activeCard`，统一移动至首屏标题与双任务卡之间；只显示一项主任务，隐藏重复的大型数据网格和次要按钮。
- 根据有效业务快照展示简要描述与下一步：待支付、预约、已估算、已保存方案、已支付待使用、用仓中、即将到期、退租中；身份未验证时保留订单详情承接，绝不绕过入仓校验。
- 多任务并存时，除主任务外提供“在我的查看”入口，不在首页叠加第二、第三张状态卡。
- 优先级：待支付 → 即将到期/退租处理/需要验证 → 已预约 → 有效方案 → 已估算 → 日常用仓。显式演示状态保持兼容。
- 首页三张通用推荐门店始终按普通浏览打开，不因已估算身份在后台强制切换成匹配模式；“继续找仓”的匹配链路仍使用原有恢复函数。
- 删除原首页已估算、已报价、用仓中的冗余大块快捷模块显示，但不删除任何旧按钮 DOM 或对应业务逻辑；推荐有礼权益移至原首页下部，不丢失入口。
- 新增 `prototype/mini_koala_home_state_integration_patch_v1.css`。任务卡独立样式控制 375/390px 宽度、单按钮、轻量内容及紧急态左侧强调。
