# Phase 2 PATCH V1 — P1 跨城市排序修复记录

日期：2026-10-10
状态：P1 代码修复完成；正式浏览器全链路、微信真机体验按用户要求本轮跳过；总发布门禁仍为 HOLD。

## 问题与证据

浏览附近门店 S01，选择北京·望京并切换“每月每立方米单价较低”后，杭州彩虹城店可能排在最前。
原因：browse/price 分支直接将全国门店放入价格排序，原“北京优先”仅在非价格排序分支生效。

## 本次修正

- S01 的 `baseOrder` 在任何距离或价格排序及其后续筛选前，先依据真实门店 `city` 字段限制为当前演示用仓城市（本版本位置选择器只支持北京市）。
- 北京实体门店之间保留原有价格低优先、同价比较到店时间的排序；距离排序仍按到店分钟数。
- 筛选无结果时保持空状态；不自动混入外省数据；考拉E存独立卡片机制未修改。
- 不修改门店与仓位母表、促销价格、租期、交易与生命周期业务逻辑。
- 当前原型仅有北京位置选项，未来如开放其他城市选择，需要同步扩展位置城市映射和路线模型，不能把当前北京市约束解释为全国多城市切换已支持。

## 回归用例与范围

新增 `qa/test_phase2_city_scope.js`：
1. 望京 + 价格排序：所有普通门店均为北京市，不出现杭州彩虹城店，价格单调不降；
2. 望京 + 距离排序：门店均为北京市，到店时间单调不降；
3. 在价格模式叠加 5km 距离筛选：不跨城且实际距离满足；
4. 距离限制 0.01km：结果为空，不自动放宽；
5. 考拉E存仍独立插入，不参加实体门店排序；
6. 有需求状态 + 价格排序、服务筛选：只返回当前城市的合格门店；
7. 全国母表中杭州彩虹城数据仍存在，证明未删除真实门店。
