# UX Conversion Friction Reduction V1 — 实施边界

## 目标
普通用户先估算、比较、选仓、下单；尺寸实操指导后移至支付后的 A01。当前门店/容量/距离/价格不完全匹配时，优先显示相近可租方案，不增加强制留资或反复劝退说明。

## 修改边界
- 修改：估算页、S01、S02、U01、支付后A01，品牌/物品估算/顾问辅助文案，旧V1.1库存演示公告。
- 不修改：真实交易/价格/优惠/押金/支付链、用户需求估算公式、城市归属、可租库存数据及库存紧迫感。
- 底线：售罄仍不可下单；更紧凑方案以容量差异标记，不伪装为完全匹配；真实距离仍保留；筛选外门店明确告知。

## 变更点
1. 取消付款前门宽、仓位形态等反复核对提示，U01保留尺寸数值（长宽高）和仓号待分配说明，隐藏演示门宽与仓体形态字段；A01的首次入仓指导继续提示联系顾问。
2. S5无匹配后首先查看仓位列表，避免被强制导入顾问留资；考拉E存仍与实体方案并列。
3. S01减少失败公告和不可用库存卡，将相近容量、实体门店和E存作为选项；筛选为空时补充真实可租的北京门店，不更改原筛选设置，并明确范围外属性。
4. S02以仓位卡/备选和附近其他门店入口引导，不重复无匹配/远距警告；保留售罄单点明确状态和不能继续租用规则。
5. U01容量小于原需求时仍显示“更紧凑，比原估算容量小”，但不强制暂停交易；超过原需求时显示更宽裕与费用口径。
6. 禁止 S02 跨店返回在租期空缺时自动携带6个月作为已确认租期。

## 验收
运行新专项 qa/test_conversion_friction_v1.cjs；历史静态与价格订单回归继续执行。真实浏览器/微信体验未验证，禁止将代码测试视作正式交付验收。
