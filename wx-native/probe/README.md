# 迷你考拉仓 · 真机验证探针工程

这不是体验版。它是一个 12 页的微信原生小工程，用来在页面开发之前，先在真机上确认平台有风险的几件事，并把结果一键复制回来。

## 怎么跑起来
1. 用微信开发者工具「导入项目」，目录选本文件夹。
2. 把 `project.config.json` 里的 `appid` 从 `touristappid` 换成迷你考拉仓小程序的 AppID。
3. 开发者工具里点「预览」用自己的微信扫码（开发版），或「上传」后在后台设为体验版，发给体验成员。
4. 手机上从首页往下逐项测，每项选「通过 / 不通过 / 测不了」，最后进「结果汇总」→「复制全部结果」，粘贴到群里。
5. 每台手机都做一遍；换手机不用清空记录。

## 什么条件下能测什么
| 条件 | 能测 |
|---|---|
| 只有游客 AppID（touristappid） | 导航栏、tab、安全区、键盘、字号、描边、横滑、长文字、地图、拨号、计时（约 15 项） |
| 换成真实 AppID | 以上全部，加隐私状态查询 |
| + 后台已填《用户隐私保护指引》并声明位置信息；位置接口已开通 | 首页自动定位、拒绝后再申请、超时 |
| + 手机号快速验证组件可用（已认证的企业主体） | 微信手机号（会消耗额度） |
| + `config.js` 填了订阅消息模板 ID | 订阅授权框、总开关 |
| + `config.js` 填了一笔 ¥0.01 测试单的支付参数 | 订阅与支付的先后顺序 |

## 记录里有什么、没有什么
- 有：机型与版本、每个接口的返回（errMsg、errno、耗时）、人工结论与备注。
- 没有：手机号、手机号动态令牌的内容、证件号、精确坐标（只留两位小数）。

## 已知限制
- 这份代码没有在微信开发者工具里编译过。我这边做了两件事：静态检查（JSON、文件齐全、WXML 结构、事件绑定）和在模拟环境里把每个处理函数各调一遍。首次导入如有编译报错，把报错原文发回来。
- 画面只用了设计令牌，没有照设计稿逐像素画；它验证的是平台行为，不是视觉还原。
- 门店名、价格、坐标、电话都是演示值。
- `tabBar` 图标和 `styles/tokens.wxss` 来自开发交接包，这次是它们第一次进微信环境。
