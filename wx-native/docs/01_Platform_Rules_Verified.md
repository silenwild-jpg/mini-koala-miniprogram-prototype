# 微信平台规则核对（W30，2026-11-18）

W28 核对时有 6 条没有查到官方原文。这次用浏览器直接打开官方文档页读到了正文，原文摘录保存在 `refs/official_docs_20261118/`。下面只写与本项目有关的条款，引号里是官方原句。

## 1. 会影响设计或实现的四条

### 1.1 定位接口按服务类目开放 —— 目前最大的不确定项
`wx.getLocation` 文档：
> 暂只针对如下类目的小程序开放，需要先通过类目审核，再在小程序管理后台，「开发」-「开发管理」-「接口设置」中自助开通该接口权限。……在代码审核环节将检测该接口是否已完成开通，如未开通，将在代码提审环节进行拦截。

国内主体开放类目（一级类目）：电商平台、商家自营、医疗服务、交通服务、生活服务、物流服务、餐饮服务、工具、金融、旅游、汽车服务、IT科技、房地产服务、政务民生、政府主体账号。其中与本业务可能沾边的三行：

| 一级类目 | 二级类目 | 官方写的应用场景 |
|---|---|---|
| 生活服务 | /（不限二级） | 上门服务作业等线下场景 |
| 物流服务 | 收件/派件、查件、邮政、装卸搬运、快递柜、货物运输 | 快递/货物收发服务 |
| 商家自营 | /（不限二级） | 提供售卖商品线下发货、线下收货服务、线下商超导览、导航服务 |

- **表里没有出现「仓储」「自助仓储」字样。** 迷你考拉仓小程序现在选的是什么类目，我不知道；它是否落在上表里，要看后台实际类目。
- 我没有读到「不在表内的类目一律不能开通」的原话，也没有看到后台的申请页面，所以结论只能是：**先查类目，再到「接口设置」里看 `wx.getLocation` 能否点开通**。这是后台准备清单的第一步。
- `wx.getFuzzyLocation`、`wx.chooseLocation`、`wx.choosePoi` 的开通条件写法不同：
  > 暂只针对具备与地理位置强相关的使用场景的小程序开放，在小程序管理后台，「开发」-「开发管理」-「接口设置」中自助开通该接口权限。

  这三个没有列类目表。`wx.openLocation`（打开内置地图看门店位置）文档里没有申请开通一节。
- 四个定位接口都要求：
  > 自 2022 年 7 月 14 日后发布的小程序，若使用该接口，需要在 app.json 中进行声明，否则将无法正常使用该接口

  声明的字段名在公告里，公告原文我没有读；探针工程按通行写法用的是 `requiredPrivateInfos`。

**对设计的影响（如果精确定位开不通）：**
- 首页「首次进入直接调定位」（D-109、D-114）、首页与门店卡的公里数、5km 内无门店（D-128）、免费运输的 5km 判断（D-173）、定位到无门店城市（D-184）都以定位点为前提。
- 设计稿已经有不依赖定位的路径：未获取位置时显示城市、用仓位置面板手动选区域或商圈。所以不是推倒重来，而是「定位点从哪来」要换：模糊定位、地图选点，或只用手动选择。
- 模糊定位的精度够不够判断 5km，我没有核对。
- 这属于平台限制，真到这一步需要你裁。现在不用裁，先查类目。

### 1.2 位置授权被拒后不会再弹窗
「授权」文档：
> 如果用户已拒绝授权，则不会出现弹窗，而是直接进入接口 fail 回调。请开发者兼容用户拒绝授权的场景。
> 开发者可以调用 wx.openSetting 打开设置界面，引导用户开启授权。
> 一旦用户明确同意或拒绝过授权，其授权关系会记录在后台，直到用户主动删除小程序。

- 验收清单 C3 的答案在文档里已经有了：拒绝过位置授权后，用仓位置面板的「使用当前位置 · 开启」不能再弹授权，只能打开设置页。
- 画面不用改，按钮文案也可以不变；实现上这个按钮在「已拒绝」时要走 `wx.openSetting`。真机上要看的变成：从设置页打开后返回，页面是否自动刷新为已定位。
- 注意区分：隐私弹窗被拒是「10 秒内再调用不弹窗」，10 秒后还会再弹；位置授权被拒是一直不弹。

### 1.3 订阅可以在支付回调之后调起
`wx.requestSubscribeMessage` 文档：
> 2.8.2 版本开始，用户发生点击行为或者发起支付回调后，才可以调起订阅消息界面。
> 限制：仅在点击行为时调用
> tmplIds……一次调用最多可订阅5条消息

- 验收清单 D8（★）担心的是「订阅框和支付在同一次点按里能否先后出现」。官方写明了一种可行顺序：**先支付，支付返回后再弹订阅**。
- 开发交接 §4.10 写的是「在按钮的点按回调里请求」，没有写先后。建议实现为：点「微信支付」→ 调起支付 → 支付回调里弹「租期到期提醒」订阅。
- 文档没有写支付取消或失败的回调算不算「支付回调」。探针里 a、b、c 三种顺序都做了，真机上各点一次就有答案。
- 一次最多 5 个模板（W28 写的是没查到）。本项目每个节点只订 1 个，不受影响。
- 错误码里与我们有关的：20004 用户关闭了订阅总开关；10005 小程序退到后台导致面板无法展示；20001 模板 ID 不存在。

### 1.4 「隐私与定位合并成一个弹窗」官方还没有写明支持的版本
「隐私协议开发指南」：
> 官方隐私弹窗将有两种样式：1）与授权弹窗耦合样式……（错误码为 103）。2）直接弹窗样式……（错误码为 104）。
> 与授权弹窗耦合样式将会在后续版本的基础库中支持（支持版本将在后续更新），在低版本基础库中所有弹窗均将采用直接弹窗样式。

- 文档到今天仍写「将会在后续版本支持」。也就是说，首页首次进入时**有可能是先后两个弹窗**（先隐私、后位置），而不是设计稿画的一个合并弹层（D-109、D-114、验收清单 C1 ★）。
- 文档可能没有跟上实际版本，所以以真机为准：探针首页一打开就会触发，记下看到的是一个还是两个，以及返回的错误码是 103 还是 104。
- 如果是两个：要么接受两个系统弹窗，要么自建隐私弹层（一个自建 + 一个系统）。到时需要你裁。

## 2. 实现时要知道的（不影响设计）

| 条款 | 官方原句 | 用在哪 |
|---|---|---|
| 隐私指引未声明 | 「{ "errMsg": "A:fail api scope is not declared in the privacy agreement", "errno": 112 } ……补充的隐私类型声明，将在 5 分钟后生效。」 | 后台没填或漏填时，定位、手机号直接报 112 |
| 提审选了未采集隐私 | 「A:fail appid privacy api banned」 | 提审时不要勾「未采集隐私」 |
| 隐私功能版本 | 「低于 2.32.3 版本的基础库未集成隐私相关功能，也不会拦截隐私接口调用。」 | 最低基础库建议设为 2.32.3 |
| 隐私弹窗再弹 | 「若距上次用户拒绝不足 10 秒，将不再触发弹窗」 | 拒绝后立刻点「开启」会无反应，要有提示 |
| 手机号令牌 | 「每个code有效期为5分钟，且只能消费一次。」 | 后端要及时换号 |
| 手机号额度 | 「用户点击button时，进行资源包额度查询。若查询额度不足，开发者将收到错误码 e.detail.errno===1400001 ，同时用户侧将收到平台默认半屏提示」 | 额度不足时微信自己会弹提示，我们再隐藏按钮、引导短信登录 |
| 手机号扣费 | 「开发者获得 bindgetphonenumber 事件的 success 回调信息时，进行扣费。」 | 用户拒绝不扣费 |
| 手机号主体 | 「目前该接口针对非个人主体，且完成了认证的小程序开放」 | 后台准备 A1 |
| 位置用途说明 | 「需要授权 scope.userLocation……时必须配置地理位置用途说明。」「授权弹窗会展示小程序在小程序用户隐私保护指引中填写的说明，请谨慎填写。」 | 用途说明要过法务，它会显示给用户 |
| 定位超时 | 「开启高精度定位，接口耗时会增加，可指定 highAccuracyExpireTime 作为超时时间。」 | 定位超时态的实现方式 |
