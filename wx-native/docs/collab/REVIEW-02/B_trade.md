## 4. 做得对、不需要改的

1. **金额全链路一致**。费用明细、底栏、变价对比、已取消的原订单金额都只读 `order.quote`，不在页面重算（services/order-view.js、core/pricing.js）。特价仓「原价 − 特价仓优惠 − 租期折扣 = 整期租金」逐行可加减。
2. **交易事件的状态处理到位**。报价过期时明细和底栏同步换占位，并关掉旧报价的弹层；仓位被租后主按钮可点、金额置灰；变价待确认时不显示「已省」、主按钮禁用并说明原因；支付失败不重新计时，四项核对卡清楚。
3. **裁定落实**。M-15（确认订单合计只留底栏）、M-16（下单人卡合并并上移）、M-18（订单卡去图）、M-21/22（快速下单预计费用并入底栏、两两合并卡）、M-25（订单详情状态头去标签）、M-26/27（协议目录默认收起、去「正文」标题）在图和源码里都能对上。9 段原文里「仓号单独设计标签、与容量同一行」在订单卡和快速下单一致。
4. **订单卡信息行分层**。距离紧贴地址、仓位编号标签 + 容量 + 尺寸分两行、租期和起租日各占一行，没有用分隔符串联。
5. **底栏主按钮按「缺哪一步」变化**（实名认证 → 签署并提交 → 继续支付 → 刷新报价 → 重新选择仓位），禁用时都写了原因。
