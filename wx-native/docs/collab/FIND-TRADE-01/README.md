# FIND-TRADE-01 找仓与交易域

基线：`dffaf2f`（COMPONENTS-01）。本批没有在微信开发者工具里编译或截图，校准按张坤 2026-11-20 的要求留到后续批量执行。

## 做了什么

### 1. 库存档位与交易事件（演示工具页新增两节）

入口：「我的」页底部 → 演示工具。只在演示数据下生效，真实接口没有这些开关。

| 库存档位 | 效果 | 能看到的状态 |
|---|---|---|
| 库存正常 | 沿用演示库存 | 默认 |
| 库存紧张 | 每家门店只剩 1 个可租仓位（各店留下的大小不同） | 容量接近、比需求大一档、门店内无匹配 |
| 附近门店满仓 | 按演示距离最近的 4 家没有可租仓位 | 已扩大范围、门店详情满仓、其他门店推荐 |
| 全城满仓 | 所有仓位不可租 | 仓位推荐无匹配、列表「当前需求暂无可租仓位」 |

| 交易事件 | 触发点 | 一次性 |
|---|---|---|
| 下单时变价 | 签署并提交时，月基价上调 ¥40，出现变价确认 | 是 |
| 仓位被别人租走 | 签署并提交时，页面进入「所选仓位已不可租」；之后找仓各页该仓位也不可租 | 是 |
| 支付失败 | 下一次支付返回失败 | 是 |
| 实名信息不一致 | 下一次实名认证返回不一致 | 是 |
| 报价 30 秒后失效 | 报价有效期 3 小时 → 30 秒 | 否 |
| 待支付 60 秒后超时 | 新订单支付时限 3 小时 → 60 秒 | 否 |
| 有一张可用券 | 确认订单带一张 12 个月长租券（租期 ≥12 个月才可用） | 否 |

- 实现：`mock/scenarios.js`（STOCK、EVENTS、take）、`services/mock-ext/_db.js`（stocked、markGone）、`services/mock-ext/trade.js`、`services/mock-adapter.js`。页面代码没有为演示加分支。
- 原来的隐藏链接参数 `&demo=pay_fail` 等仍可用。
- 「报价 30 秒后失效」打开时，页面文案仍写「报价已超过 3 小时」（文案按正式规则，不跟演示开关变）。
- 切换演示场景不会重置库存档位和交易事件。

### 2. 新增 2 个演示场景

- 访客按面积找仓：6㎡（约 15m³）租 12 个月。
- 访客大容量需求：35m³ 租 12 个月（≥30m³ 只提示顾问，仍可自助）。

### 3. 空态与提示条迁移（找仓、交易两域清零）

- `mk-empty`：仓位推荐 2、附近门店 2、门店详情 3。
- `mk-notice`：仓位已售出 / 不可租 4 处、附近没有门店 1、报价过期 1、支付失败核对卡 1、订单详情说明 2、协议未上线 1。
- 实名弹层两项改 `mk-field`。
- 删掉 38 条页面样式。`static_check.py` 的 `PENDING_HANDWRITTEN` 只剩线索域的 `lnd-notice` `ldf-notice`。

### 4. 修复与补齐

- 预计用仓时间（评审 ccc9b15 的 P2）：确认订单页不再接受链接带入的范围外日期，下单接口同步校验。
- 确认订单、订单详情、快捷下单的加载态改为骨架屏。
- 确认订单底栏主按钮、实名提交、快捷下单「下一步」补按压反馈。
- 测试里写死的 `2026-12-01` 改为相对今天的日期（否则 12 月 1 日后这些用例会失败）。

## 要在开发者工具里确认的点（批量校准时一起看）

1. `mk-empty` 插槽里第三个子节点：仓位推荐无匹配态的「立即咨询」文字按钮应独占一行居中；附近门店转顾问态的服务时间说明应独占一行。
2. `mk-notice` 插槽里的核对四行（确认订单支付失败态）左右对齐是否正常。
3. `mk-notice` 的 `link` 在报价过期提示里是否好点（点击区高度）。
4. 门店详情 `mk-empty` 宿主节点上的 `class="sd-emptygap"` 外边距是否生效。
5. 骨架屏在确认订单页是否被底栏遮住。
6. 演示工具页新增两节的行高与「已打开 / 未打开」标签对齐。

- 门店卡、门店详情的库存紧张提示（如「仅剩 1 个」）：属于新增展示规则，没有自定。
