# ORDERS-AFTER-01 订单与租后域

基线：`8576588`（FIND-TRADE-01）。本批没有在微信开发者工具里编译或截图，校准留到后续批量执行。

## 做了什么

### 1. 租后演示场景（演示工具页新增 8 个）

| 场景 | 打开后看哪里 |
|---|---|
| 续租报价待确认 | 续租页：报价卡、24 小时倒计时、确认并支付 |
| 退仓待清空 | 退仓页：已提交到期退仓，待申请验仓 |
| 验仓未通过 | 退仓页：失败卡带原因，可重新申请验仓 |
| 押金退款未成功 | 押金页：失败卡带原因，进度停在退款处理 |
| 开票未成功 | 发票页：失败卡带原因，表单预填原资料 |
| 实名未通过 | 实名认证页：未通过，可重新提交资料 |
| 订单已取消和已超时 | 订单列表、订单详情的两种关闭态 |
| 多门店多笔订单 | 3 家门店 8 笔，订单列表和首页任务卡的排序与各阶段标签 |

- 写法：`mock/scenarios.js` 的订单描述里加 `after: { renew, exit, deposit, invoice, identity }`，由 `services/mock-ext/_db.js` 的 `applyAfter` 摆到对应步骤。
- 等门店处理的状态（续租已提交、待验仓、开票中）按「刚刚提交」造，打开后几秒会自动推进；要停住看，打开下面的「门店暂不处理」。

### 2. 租后事件（演示工具页新增一节，5 个开关）

| 事件 | 触发点 | 一次性 |
|---|---|---|
| 续租支付失败 | 下一次续租付款 | 是 |
| 验仓未通过 | 下一次申请验仓后门店返回结果时 | 是 |
| 押金退款未成功 | 下一笔押金退款到点时 | 是 |
| 开票未成功 | 下一张发票开具到点时 | 是 |
| 门店暂不处理 | 续租报价、验仓、退款、开票、实名审核全部停在等待中，关闭后继续 | 否 |

- 原有的「实名信息不一致」现在对付款后补认证也生效。
- 续租报价过期与门店无关，「门店暂不处理」打开时照常发生。
- 验仓未通过、退款未成功、开票未成功以前只能在测试里改数据才出现，现在可以在界面上走到。
- 新增两条消息：押金退款未成功、发票开具未成功（验仓未通过的消息文案原来就有，以前不会发出）。

### 3. 修复

- **待验仓阶段**：已申请验仓的订单，订单详情和首页任务卡现在显示「等待门店验仓」。原来的判定条件和数据字段对不上，这个阶段一直不会出现。
- **演示造单**：已取消、已超时的演示订单不再带付款时间和签署记录。

### 4. 页面层

- 订单列表、租后七页加载态改为骨架屏。
- 租后四页底栏按钮按种类给按压反馈；续租页文字入口加按压底色。
- 实名认证页弹层报错改用 `mk-field` 的报错位。
- 租后七页原来各带一份相同的公共样式，合并为 `pkg-after/after.wxss`，各页 `@import`；分包样式从约 20.6KB 降到 9.6KB。
- 近似预览和按钮量宽两个工具现在会展开 `@import`（以前直接丢掉，账户分包的公共样式在预览里其实没有生效）。

## 要在开发者工具里确认的点（批量校准时一起看）

1. `@import "../after.wxss"` 在分包内是否正常解析（账户分包已有同样写法）。
2. 底栏按钮 `hover-class` 用了数据绑定表达式，四种按钮按下的颜色是否各自生效。
3. 骨架屏在租后页的左右边距、与底栏是否重叠。
4. 续租页「暂不续租」按下的底色范围。
5. 实名弹层报错文字与输入框的间距。
6. 演示工具页现在有 20 个场景，列表较长，「回首页查看」按钮在列表之后。

## 没做的

- 订单列表的筛选或分组（按进行中、已结束）：冻结稿没有，属于新增交互，没有自定。
- 续租报价有效期的演示缩短开关：有效期在规则层计算，没有为演示加分支。
- 押金退款未成功之后的恢复：演示环境停在失败态，正式环境由门店处理。
- 消息页、看仓弹层手机号错误提示、线索域提示和表单迁移：下一批「账户和留资」。
