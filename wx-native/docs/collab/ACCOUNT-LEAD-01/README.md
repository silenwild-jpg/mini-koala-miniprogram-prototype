# ACCOUNT-LEAD-01 账户与留资域

基线：`653089d`（ORDERS-AFTER-01）。本批没有在微信开发者工具里编译或截图，校准留到后续批量执行。

## 做了什么

### 1. 演示场景（演示工具页新增 7 个，共 27 个）

| 场景 | 打开后看哪里 |
|---|---|
| 有预约记录 | 预约记录页：个人预约、企业需求、预约看仓、已撤回的咨询各 1 条；「我的」页显示条数 |
| 消息较多 | 消息页：7 条消息 3 条未读，各分类都有，点进对应订单的租后页；「我的」页消息角标为 3 |
| 有收藏（含已失效） | 我的收藏：3 家门店 2 个仓位，其中 1 家暂停营业、1 个仓位已租出 |
| 已领新客券 | 优惠与权益：2 张券可用、1 项运输权益 |
| 企业认证审核中 | 企业认证页审核中（几秒后出结果；配合「审核暂不处理」可停住） |
| 企业已认证 | 企业认证结果页、开票抬头、批量开票 |
| 企业认证未通过 | 企业认证页失败态带原因，可更正后重新提交 |

- 写法：`mock/scenarios.js` 的场景上加 `leads` `messages` `favorites` `account`，各适配器第一次取数时按当前场景造（`mock-ext/lead.js seedLeads`、`after.js seedMessages`、`account.js fromScenario`），收藏写进本机状态（`services/demo.js`）。
- 「多门店多笔订单」「消息较多」共用同一组 8 笔订单（`MULTI`）。

### 2. 留资与账户事件（演示工具页新增一节，7 个开关）

| 事件 | 触发点 | 一次性 |
|---|---|---|
| 提交失败 | 下一次提交预约、咨询、运输或看仓需求，不落库，可重试 | 是 |
| 提交结果未确认 | 下一次提交已落库但回执超时，页面提示核对结果，核对不重复建单 | 是 |
| 按非服务时段受理 | 提交后一律显示非服务时段的受理文案 | 否 |
| 验证码发送失败 | 下一次获取短信验证码 | 是 |
| 企业认证未通过 | 下一次企业认证审核出结果时 | 是 |
| 批量开票未成功 | 下一次批量开票出结果时 | 是 |
| 审核暂不处理 | 企业认证、批量开票停在处理中，关闭后继续 | 否 |

- 表单校验没过时不消耗一次性事件。
- 原来靠企业名含「驳回」、邮箱以 `fail` 开头触发失败的做法仍保留（测试在用）。

### 3. 修复

- **联系电话组件的「修改」和弹层「完成」没有文字**：文字表里缺这两个键，按钮渲染为空。已补。
- **看仓弹层已登录时的手机号报错**指向一个此时不显示的按钮（上轮评审 P3）。已改为按登录态给不同句子。
- **成功色标签看不清**：「可使用」「已认证」「租用中」「已验证」原来是深绿底配深绿字，对比度约 1.6。改为浅绿底。
- **联系电话验证码发送失败时没有提示**：接口没带报错句时页面什么都不显示，已补兜底句。

### 4. 页面层

- 留资四页、预约记录修改弹层、联系电话验证弹层、看仓弹层的表单项改用 `mk-field`（共 30 处）。
- 留资页的状态条、运输页和预约记录页的说明条改用 `mk-notice`；全站手写提示条清零，`static_check.py` 的豁免名单已清空。
- 状态标签合成一套 `mk-tag--ok / warn / err / info`（加 `mk-tag--end` 放行尾）；中性按钮合成 `mk-btn--plain`；删掉 5 套分包自带标签和 3 套中性按钮样式。
- 账户 11 页、留资 4 页整页加载改为骨架屏，外框 `mk-sys-wrap`。
- 消息页：未登录显示「登录后查看消息」和登录按钮；可跳转的行有按压反馈；未读标题加粗。
- 预约记录「更多操作」弹层、联系顾问「预约用仓」两行改用 `mk-cell`。
- 补按压反馈：联系电话「修改」「获取验证码」、预约结果页「开启通知」、E存「查看禁存清单」、企业页底栏四个按钮（禁用时不反馈）、看仓弹层日期选项和按钮。
- 看仓弹层文字全部移进 `i18n/lead.js` 的 `visit`。

## 要在开发者工具里确认的点（批量校准时一起看）

1. `mk-field` 上写的页面类（`ldf-fld`、`ldf-fld--first`）是否作用到组件节点：相邻表单项间距应为 48rpx，卡片内第一项不应多出上边距。
2. `mk-cell`、`mk-notice` 上直接绑 `bindtap` / `bind:link`，在预约记录弹层、联系顾问页、预约页失败条上是否可点。
3. 看仓弹层：两个选择器是否并排等宽；输入框聚焦时键盘是否顶起弹层；`picker` 内的自绘行高度。
4. 消息页行的按压底色是否铺满整行（卡片有左右内边距）。
5. 嵌套的 `mk-field`（企业页「其他用仓区域」在「用仓位置」项内）间距是否正常。
6. 骨架屏在账户、留资各页与导航栏的间距；断网态按钮宽度。
7. 演示工具页现在有 27 个场景、19 个事件，页面很长，校准区在最后。

## 没做的

- 预约提交后自动写一条「咨询」类消息：消息分类里有这一类，但冻结稿没有对应标题，没有自拟。
- 预约页「存放物品 / 意向容量 / 预计租期」三行没有换成 `mk-cell`：它们右侧要区分已选值和占位色，公共行组件只有一种说明色。
- 账户分包里 `pf-neutral`、`et-neutral`（深色字的描边按钮）没有并入 `mk-btn--plain`，它们的按压反馈是幽灵按钮那一种。
- 演示场景没有分组或搜索；27 个平铺。
- 风格层（卡片投影、首页场景图、底部导航图标）：下一批。
