# GAPS-01：评审前补缺口（库存紧张提示、预约提交后的消息）

张坤 2026-11-20 对四个缺口的答复：库存紧张提示添加；多笔订单的筛选或分组不需要；预约提交后生成消息；押金退款未成功后的恢复路径待业务裁定。

## 做了什么

### 库存紧张提示

- 口径：门店可租仓位总数为 1 到 2 个时，显示「仅剩 N 个可租」。满仓不显示（已有「暂无可租仓位」）。
- 位置：门店卡标签行（附近门店、仓位推荐）、门店详情标签行。占一个标签位，标签行仍最多两个。
- 首页推荐卡没有加：卡片窄，标签行只放得下两个短标签。
- 开关与阈值：`core/config-find.js` 的 `lowStock`（`show`、`maxLeft`）。文案在 `i18n/find.js` 的 `stock.low`。
- 演示方法：演示工具页把库存档位切到「库存紧张」，每家门店只剩 1 个可租仓位。

**与既有裁定的关系**：D-170（W22「压力文案收敛」）和交接 v1.0 §门店列表卡写的是「不显示剩余数量」「不显示『同容量仅剩这 1 个』一类库存提示」；`docs/next-stage-20261120` 也写了真实库存口径建立前不声称「仅剩」。这次按张坤 11-20 的新要求加回，登记为 PR-40。旧冻结稿的口径是「同容量仅剩 N 个」，演示库存里每家门店各容量只有 1 个仓位，照搬会每一行都出现，所以改为按门店总数。

### 预约提交后生成消息

- 预约用仓、顾问咨询、企业用仓、预约看仓四类线索受理后，各写一条未读消息，分类「咨询」，可进预约记录页。
- 同一个 `request_key` 重复提交不重复生成；提交失败不生成；「提交结果未确认」属于已受理，会生成。
- 运输预约和客服留言不生成（它们不在预约记录页里）。
- 四句标题是自写的，在 `i18n/after.js` 的 `messages.demo.lead*`，登记为 PR-41。
- 写消息的函数移到 `services/mock-ext/_db.js` 的 `pushMessage`，租后和线索共用。

### 没做的

- 多笔订单的筛选或分组：张坤答复不需要。
- 押金退款未成功后的恢复路径：待业务裁定，登记为 PR-42；演示环境仍停在失败态。
