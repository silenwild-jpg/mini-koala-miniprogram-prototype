## 2. 更新后的产品展示方案

库存展示重点是可租性与容量适配。全店数量不默认主显；完整库存数据仍支持筛选、占用核对和下单重验。这个取舍是当前产品判断，尚无真实用户实验；后续观察找仓完成情况、回看详情原因与无匹配退出原因，不凭图标数量或卡片变短推断转化提升。

| 信息层 | 默认展示 | 次级查看位置 / 约束 |
|---|---|---|
| 选仓必需 | 门店、距离/位置、仓号与体积、起价/正式价口径、容量偏小、组合事实、可操作状态 | 无库存、价变、失效、偏小不藏到二次点击；不删“小 Xm³” |
| 适配核对 | S02 的长宽高/面积、组合各仓编号、完整地址和服务 | 沿已有详情、页签、费用明细、组合展开入口查看；核对实际能否放入还涉及门型、长件与有效高度，体积接近不保证实物可装入 |
| 解释与规则 | 计价组成、优惠条件、服务条款、完整资料 | 优先复用已有费用弹层、详情和协议；纯说明不默认新建弹窗或卡片 |
| 运营信息 | 全店库存数量、原始仓位状态和释放记录 | 数据模型保留；正式可租口径和刷新保证未建立前，不声称“实时”“仅剩”或虚构更新时间 |

**已实施的密度基线：** S01/S5 门店标题区最多两个标签位（包含推荐标记）；S01 不再主显“另有 N 个可租”；列表不重复泛化用途、仓型/面积和升级理由；S02 保留尺寸、面积并去掉泛化用途；QUICK 门店选择层突出距离和地址，售罄明确提示。

**下一阶段的检查规则：**

- 逐块标出任务、主信息、次信息、行动；没有独立决策价值的重复句优先删除或合并，不能通过不断缩小字号解决拥挤。
- 标签预算只约束门店标题区，不机械推广成“整张卡只能两个标签”；“小 Xm³”等风险信息不占可随意裁剪的营销标签位。
- 每个独立可选方案保持一个明确主行动；多个仓位的选择按钮可以并列存在，不为了“一屏一个按钮”破坏列表选择。
- 主价格、币种/单位、偏小提示、组合数量、错误与主按钮不得省略或使用省略号。长地址可在摘要中截断，但必须能从已有详情入口查看完整内容；在 S02 核对完整地址的可达性。
- 非通用图标保留文字标签；图标按钮有可访问名称；状态不只靠颜色。优先扩展点击区域达到约44逻辑像素，不能把44rpx误当44px；确有冻结结构冲突先记录影响。
- 小屏、长中文名称、整期大金额、软键盘、安全区及系统字体放大均进入检查。对比度重新测量，不继承历史“占位/灰字全部豁免”的笼统结论。

## 3. 业务硬边界

以下是已批准运行时规则，不属于视觉升级可自由改动的内容：

- ≥30m³继续自助选仓与下单，只轻提示顾问；足额先于接近，接近门槛80%，明确偏小。
- 容量输入结束后向上归一到一位小数；低于下限建议0.5m³/0.2㎡；面积上限200㎡，暂按2.5m换算，保留原单位与原输入。
- 特价九折与既有租期折扣按现规则计算；券、满额减、运输资格、组合逐仓取整和订单快照不在UI重算。
- 正式报价与进入订单仍受登录验证约束；QUICK来源回QUICK；O01失效会话不能露出游客订单内容。
- S5修改回原需求来源CAP/ITEMS；U01不恢复为中间必经页；S02可直接进入订单。
- 看仓是S02页内弹层，提交独立销售线索；不创建订单、不锁仓；失败保留输入、超时同请求核对。
- ITEMS超过15m³或含大件任一成立即轻提醒，可继续。取消演示订单释放共享库存的既有逻辑保留。

## 7. 并行准备、决策与成本

真实库存契约应明确：仓位实体与可租状态、容量和有效尺寸来源、占用/取消/过期释放、报价版本与有效期、幂等、最终确认时的库存/价格重验、库存未知/过期/冲突的前端反馈。字段方案是待接口负责人核实的建议，不等于已有端点。未接真实服务前维持mock隔离，不仅切换 `DATA_SOURCE` 即宣称接入完成。

待确认项与风险见[DECISIONS_AND_RISKS.md](DECISIONS_AND_RISKS.md)。本轮不反复索要已给出的AppID，不重新询问“两标签/不主显库存总数”这些已实施方向；只在实际冻结结构冲突、正式政策、真实资料或权限不足时定点处理依赖项。

**工作量与排期：** 暂不承诺具体工期。01A完成后按“实际组件数×变体/状态×调用页面”估算改动和回归，工具恢复等待、资料等待与开发工作分开记；01C完成后再校准01D批次。每批只报告完成、证据、遗漏及下一编号，不因完成一小步停下来等“继续”。

主要成本在共享组件传播回归、价格/鉴权等高风险状态、真机与资料核验；换图标本身通常不是主成本。减少说明文字可能降低理解，转入详情也会增加点击，必须在试点验证可发现性，而非把所有说明改成图标或弹窗。
