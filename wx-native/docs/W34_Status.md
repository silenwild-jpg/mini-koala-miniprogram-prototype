## 本轮整合时我改的
1. 按钮：`app.json` 开了 `style: v2`，原生 button 默认宽 184px。`.mk-btn` 补了 `width: auto; min-height: 0`。没有编译验证，真机上按钮宽度是第一批要看的。
2. 已选仓位：进入确认订单时写入全站 `selection`，下单成功后清掉，同时清空物品估算清单。找仓进度页的「已选仓位 / 报价」三态由此可达。
3. 入仓指引 → 门店详情的到店指引页签参数对齐。
4. 填容量页容量错误句换成冻结稿原文「请填写不小于 0.5m³ 的容量，最多两位小数」，同步改了测试。
5. 新增共享约定：订单对象只在 `core/order-model.js` 构造；演示订单 5 笔（`DEMO_SEED_ORDERS`）；接口按域拆在 `services/mock-ext/`。

## 演示环境的约定（接真实接口后不存在）
- 登录：短信验证码任意 6 位；微信取号任何结果算成功。个人信息页更换登录手机号时，新号码尾号 0000 → 号码冲突。
- 实名：任意合法格式的姓名和 18 位身份证号通过。
- 支付：不调用微信支付、不扣款，默认成功。演示支付失败、变价、带券、实名不一致：确认订单页地址加 `&demo=pay_fail`、`price_changed`、`coupon`、`idv_mismatch`，界面上没有入口。
- 租后：门店报价、验仓、退款、开票、实名审核按 `core/config-after.js` 的间隔自动推进。
- 企业：企业名含「驳回」→ 认证未通过；邮箱以 fail 开头 → 开票未成功。

## 已知缺口
- 登录层不外传「用户拒绝授权」，预约 / 企业页拿不到拒绝态的专用说明句。
- 仓位占用只记在交易侧，找仓各页看不到刚被下单占用的仓位。
- 营业执照只在本机选图，没有上传；发票下载在演示环境没有文件。
- 撤回隐私授权：微信没有代用户撤回的接口，现在是退出登录并清掉本机标记。
- 订阅模板 ID 没填：四个节点都不会弹订阅框，结果页也不出通知行。
