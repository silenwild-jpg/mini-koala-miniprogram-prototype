# 迷你考拉仓小程序 · 开发任务书 v1.0

2026-11-18 · W32 · D-200（由设计侧助理启动真实代码开发）· 路线：微信原生（D-194）· 设计基线：W27 冻结稿（D-193）· 规则基线：《开发交接 v1.0》+ D-198

## 1. 目标与范围

照冻结稿新建一个微信原生小程序，先出**体验版**：演示数据、找仓与交易主路径可在微信里走通；之后补租后与其余页面，最后接真实接口。

- 现行页面 35 个、状态 578 个（D-198 撤回 2 个）。
- 本任务书管代码；设计稿冻结期间只改缺陷、业务与法务口径、财务定档数字。
- 仓库里 11-14 的旧 Web 原型不在范围内，不改。

## 2. 分工与我做不了的事

| 事项 | 谁做 |

## 3. 完成门槛（每批都要过）

1. 单元测试与流程测试全部通过（`node --test tests/`）。
2. 静态检查 0 错误（`python3 tools/static_check.py miniprogram`）：四件套齐全、事件函数存在、路径存在、不跨分包引用、样式只用令牌、组件类名不撞、各包不超过 2MB。
3. 模拟运行 0 报错（`node tools/smoke_run.js miniprogram`）：已登录 / 未登录 × 有需求 / 无需求 / 30m³ × 接口成功 / 失败。
4. 本批页面的状态逐个对照状态矩阵，列出「已做 / 未做」；金额类与冻结稿规则脚本对账。
5. 微信开发者工具编译 0 报错。
6. 真机走查：按《真机验收清单》本批相关项，问题分「缺陷 / 业务口径 / 平台做不了」。

提交体验版评审前另加两条：占位页清零；界面里没有写死在模板里的文案。

## 6. 本轮我自定的做法（不否决即保留）

1. 未登录进入仓位推荐页不自动弹登录层，点「查看报价」才弹（交接 §8 第 1 项的建议）。
2. 体验版先用演示数据，接口层留好（交接 §8 第 3 项的建议）。
3. 未登录、且没有用仓需求时直达确认订单：落到「我的」并打开登录层（D-198 写的是落到仓位推荐页，但没有需求时那一页显示不了）。
4. 演示环境的登录：微信取号任何结果都算成功；短信验证码任意 6 位数字通过。只在演示数据适配器里，接真实接口后不存在。
5. 未登录时顾问卡只按容量（超过 15m³）判断，不按整期金额，避免通过顾问卡间接透露金额档位。
6. 门店详情先用原生导航栏：没有核验过的门店实拍，照片位暂不渲染。
7. 填容量页 30m³ 及以上、非服务时段的那句话是我写的：「提交后顾问上班将优先联系您。服务时段：每日 9:00–20:00」。
