## 本轮最终规则

| 项目 | 当前有效规则 | 明确覆盖 |
|---|---|---|
| 大容量 | ≥30m³继续匹配、选仓、组合与下单，仅轻量提示顾问 | `salesOnly`强制分流、企业按30m³带入后阻断 |
| 容量接近 | 仓位容量≥需求80%且小于需求，可纳入推荐候选；保留偏小属性，显示“小 Xm³” | 上轮10%／90%阈值；不能将偏小仓位显示成足额容量 |
| 特价仓 | 每店演示分配1–3个可租特价仓；基价九折后叠加既有租期折扣 | 特价仓与租期折扣互斥 |
| 容量输入 | 不因小数位多报错；输入结束归一化为向上最多一位小数；低于下限给建议下限并继续 | 小数位数、低于下限即阻断 |
| 面积 | 最高200㎡；暂按2.5m换算容量 | 2.4m／80㎡旧参数 |
| S02看仓预约 | 页内弹窗；带入门店；快捷填手机号、看仓时间、可选容量与仓位；提交销售线索 | 独立看仓页面方案；不删除其他现有预约用仓页面 |
| ITEMS提醒 | 超过15m³ OR 含大件，任一成立即轻提醒，可关闭继续 | 必须同时满足；常驻抢占主行动的顾问说明 |
| S5修改 | 回需求来源CAP或ITEMS，预填并保存草稿 | S5常驻租期控件和修改需求弹层作为主编辑路径 |
| 登录 | 订单前仍需验证；清除O01游客内容；提示“请登录”；QUICK来源回QUICK | 游客进入O01后再登录 |
| 预约成功 | 提交后直接成功态；订阅邀请不阻挡成功 | 先订阅再到成功 |

“容量接近可匹配”不保证实物一定能装入。足额、接近、组合仍保留可区分的数据属性，供排序和UI展示；不把80%改为所有候选都优先于足额方案。未修改的排序规则仍沿用Claude包。

## 输入与匹配验收例子

- 3.01m³ → 建议3.1m³；3.1 → 3.1；0.11m³ → 建议0.5m³，可继续。
- 0.11㎡ → 建议0.2㎡；2㎡ → 暂按5m³；200㎡可进入找仓，超过200㎡仍按上限校验。
- 空值、非数字不伪造成有效需求。原输入值、单位、归一值分别保存；不要在逐字符输入时抢改输入框。
- 需求10m³：8m³纳入接近候选，标“小2m³”；7.9m³不属于容量接近；10m³为足额；超过需求仍按现有更大仓位规则。
- 29.9、30、30.1m³均可继续筛选选仓，30不再跳到只有顾问的页面。无库存时按无匹配呈现，不伪造库存。
- 15m³且无大件不触发ITEMS这条提醒；15.1m³无大件触发；3m³有大件也触发。

## 计价执行解释与边界

九折是乘法：基价1000元、6个月系数0.7时，月租为1000×0.9×0.7＝630元，不是“七折减一折”。工程默认沿用现有月租向下取整，只在乘完系数后统一取整；混合组合逐仓计算再累加。本项属于工程解释，应在金额测试中固定。

本次明确批准九折与现有折扣叠加，没有新增“所有优惠无条件叠加”的规则。券与满额减原有取优关系、续租参与条件暂沿用Claude包；特价相关门禁逐项核查，不凭历史记忆自动改写。押金、整期租金、费用明细、节省金额均使用同一报价结果，不在UI另算。

演示特价用固定种子分配，重开和截图不随机跳价格；若某店可租仓位不足3个，只在已有可租范围分配，缺库存单列。不改变已签订单快照。

## 看仓弹窗实施默认值

- 门店只读带入；已选仓位可选带入，未选不强迫先选仓；容量选填，继承已有需求。
- 手机号必填，已有验证手机号预填；游客优先微信取号，失败或拒绝可手填。手填线索电话不等于验证登录。
- 看仓时间提供快捷日期和时间段，可选其他时间或待电话确认；不伪造门店实际可约时段。
- 提交创建看仓销售线索，含门店、来源页面、电话、时间偏好及可选需求；不创建订单，不锁仓。
- 提交中防重复，失败保留输入，成功在页内展示结果，再回S02；键盘和安全区均需微信验证。
- 微信在线客服入口由账号能力和配置决定。没有配置时如实显示可用的联系路径；不得把复制文本或空链接记为“客服已接通”。

这些是用户授权“快捷选择与提交”的工程默认方案，未增加独立页面或强制注册门槛。
