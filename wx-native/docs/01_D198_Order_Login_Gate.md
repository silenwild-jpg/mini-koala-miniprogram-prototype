# D-198 确认订单前手机号注册强制拦截

张坤 2026-11-18 裁定：**确认订单前手机号注册强制拦截，未注册禁止访问确认订单及后续页面。**

本文取代《开发交接 v1.0》§4.1 第 3 条里「确认订单……不显示金额与费用明细，费用行写『登录后显示』，主按钮『查看报价』」中关于**确认订单页**的部分（快捷下单页的写法不变）。

## 1. 规则

1. **受限页面**
   - 确认订单页（O01），含它上面的实名认证、签署、支付弹层和支付结果。
   - 其后的页面：订单详情（O03）、续租（RN01）、退仓（EX01）、押金（DP01）、发票（IV01）、电子合同、订单内的实名认证页。
2. **进入条件**：已完成手机号验证。手机号验证通过即登录，未注册的手机号自动注册（D-110，不变），所以「已注册」和「已登录」是同一个判断，不另做注册页。
3. **未登录时点「立即下单」「下一步」**：不跳页，在当前页打开登录层（仓位推荐、门店列表、门店详情、快捷下单四处）。登录成功回到原页，显示整期价，用户再点一次进入确认订单（D-121，不变）。
4. **未登录时直接到达受限页面**（分享卡片、扫码、订阅消息、历史页面栈、手动输入路径）：
   - 确认订单 → 重定向到仓位推荐页并打开登录层，提示「请先登录，登录后才能确认订单」；来自快捷下单的回快捷下单页。
   - 其后的页面 → 重定向到「我的」并打开登录层，提示「请先登录，登录后查看订单」。
   - 用 `redirectTo`，不留受限页在页面栈里，登录层关闭后按返回不会回到受限页。
5. **登录状态在受限页内失效**（会话过期、换绑、退出登录）：下一次进入或下一次请求时按第 4 条处理。
6. **服务端同样校验**：报价、下单、签署、支付、订单查询接口对未登录请求一律拒绝。前端守卫只管体验，不能当成安全边界。
7. **不受限**：首页、估算、门店列表与详情、仓位推荐、快捷下单的选择步骤、预约用仓、联系顾问、企业页、协议文本、「我的」游客态。

## 2. 撤回的状态

| 页面 | 状态 | 处理 |
|---|---|---|
| 确认订单 O01 | `unauthorized`（未登录的确认订单页） | 撤回，不实现 |
| 确认订单 O01 | `unauthorized` + `overlay=phone`（确认订单页上的登录层） | 撤回，不实现 |

- 现行状态数 580 → **578**。第 2 批（交易）96 → 94。
- 冻结稿（W27）的文件没有改：这两个状态的画面仍在稿里，只是不再属于现行范围。《页面与状态矩阵》里这两行按撤回处理。
- 不需要新画状态：四处入口页的登录层（`auth=phone`）原来就有。

## 3. 设计侧自定的判断（不否决即保留）

1. 「注册」按 D-110 理解为手机号验证通过，不另设注册表单。
2. 拦截范围里的「后续页面」按上面第 1 条的清单理解。订单列表（OH01）未登录时仍可打开，显示空态和登录入口。
3. 直接到达确认订单时的落点是仓位推荐页；小程序里如果带了门店或仓位参数，建议落到对应的门店详情页，这一点留给开发按参数决定。
4. 登录成功后停在原页，不自动跳进确认订单。原因：登录后价格位从「/月起」变成整期价，用户应先看到这个数再下单。
5. 快捷下单未登录时主按钮仍是「查看报价」，点了出登录层；选择门店、仓位、租期这几步不拦。

## 4. 可点击 HTML 版里的实现与核对

- `pages/proto-nav.js`：新增进入守卫；「立即下单」「下一步」未登录时不再去 `o01.html?state=unauthorized`。
- `demo.html`：第 4 组第 2 屏由「确认订单 · 未登录」换成「未登录点『下一步』：先登录」；41 个受限画面的链接带 `as=member`，表示以已登录用户身份查看。
- 端到端流程 14 条 87 步全部通过，其中新增 3 条：未登录直接打开确认订单（3 个地址）、未登录直接打开订单详情等 7 个页面、目录身份参数。
- 全站跳转核对：未登录身份下逐个状态问 15,357 个可点元素「会去哪」，没有规则的为 0。指向受限页的有 43 个，全部来自首页和「我的」的已有订单状态（这些状态本身只有登录后才会出现），游客状态下为 0。
- 没做：微信开发者工具和真机上的验证；小程序里要用页面 `onLoad` 守卫加接口鉴权实现，网页版只是演示这个行为。

## 5. 给开发的增量（并入《开发交接 v1.0》）

| G-2 | 「立即下单」「下一步」在未登录时调用同一个登录层，不 `navigateTo` 确认订单 |

| G-4 | 报价、下单、签署、支付、订单查询接口对未登录请求返回未授权；前端收到后按规则第 4 条跳转 |
