## 三、新发现

### RC9-01（P1）主按钮被微信默认的 184px 宽度锁死

**现象**：不同页面、不同文案的主按钮宽度完全一样，375 和 390 两个宽度下也不变。我对截图做了像素测量，换算回逻辑像素：

| 按钮 | 所在图 | 运行时宽度 | 冻结稿 W27 |
|---|---|---|---|
| 微信手机号快捷登录 / 其他手机号登录 | C05 | 约 183 | 343（通栏） |
| 查看报价 | C02 | 约 183，单独占一行居中 | 104，与价格同行靠右 |
| 立即下单 | C07 | 约 183 | 104 |
| 实名认证 | C04 | 约 183 | 144 |
| 提交看仓需求 | C08 | 约 183 | 无对应稿 |
| 其他租期「确定」 | C09 | 约 183 | 无对应稿 |

对照图：`button_width_compare_375.png`。

**原因**：`app.json` 开了 `style: v2`，微信给原生 `button` 加了默认宽度 184px 和左右自动外边距，`.mk-btn { width:auto; margin:0 }` 压不过它。这一点 Codex 本批已实测确认（STATUS.md：仅设 width/min-width 仍被覆盖），但只给门店页两个按钮加了 `max-width`，明确写了「不推广公共样式」。仓库里 `pages/mine/index.wxss:28` 和 `pkg-account/acc.wxss:2` 的注释也记了同一个问题，那两处做了页面级复位。

**影响**：登录、看报价、下单、提交留资这条主路径上的按钮都不是设计宽度。仓位推荐卡里按钮掉到下一行，每个仓位多占一行高度，和本分支「降低展示密度」的目标相反。工程里共 188 个 `<button>`、分布在 45 个 WXML 文件，哪些受影响需要 Codex 在开发者工具里排查。

**要求**：
1. 在公共样式层一次复位，写法以开发者工具实测生效为准；
2. 复位后每类按钮要有明确宽度（通栏、定宽或随内容），不能只是去掉 184；
3. 这是共享样式变更，按协议先发影响清单，再改；
4. 回归图至少覆盖上表 6 处，375/390 各一张。

说明：我对 76916af 的评审看过同样的截图，没有发现这一条，是我漏了。

### RC9-02（P2）CSET-01 日期差异：大概率是采集工具传参，不是产品回归

- 我在 Node 模拟环境用同样的参数打开确认订单页：`date=2026-12-01` 时页面和订单卡都显示 2026-12-01；不带 `date` 时显示 2026-11-21。**代码路径正常。**
- 截图里租期 12 个月、日期 11-21，恰好都是不带参数时的默认值，只有第一个参数 `unit` 生效。这和「URL 在第一个 `&` 处被截断」吻合。
- 采集脚本通过 `wechatide.cmd` 传 URL，`.cmd` 经 cmd.exe 时 `&` 是命令分隔符。**这是推断，我没有 Windows 环境，未验证。**
- 鉴别方法：把 URL 里的租期改成非默认值（如 `term=6`），并在回执里记录 `page.options`。如果租期也回到 12，就是截断。
- 在确认前，两张 C04 图只能当作「默认日期的确认订单页」的证据，继续标 FAIL 是对的。

### RC9-03（P2）确认订单页接受范围外的日期

- 日期选择器限制在明天起 90 天内，但 URL 入参只校验格式。我实测 `date=2020-01-01` 和 `date=2099-01-01` 都被接受并显示。
- 模拟下单接口同样只校验格式，过去的日期可以下单成功。
- 要求：`onLoad` 对范围外的日期回退到默认值；下单接口拒绝范围外日期；各补一条测试。
- 90 天上限在 `config-trade.js` 里标的是「自定」，不是已批准规则，见文末待裁项。

### RC9-04（P3）已登录用户的手机号错误提示指向一个不存在的操作

已登录时「使用微信手机号」按钮不显示，但错误提示仍写「请填写有效手机号，或使用微信手机号」。实际的恢复方式是清空输入框，沿用已验证号码（Codex 新增的第 2 条测试验证的正是这条路径）。建议已登录时改为「请填写有效手机号，或清空后使用已验证手机号」。

### RC9-05（P3）门店页「分享」右边缘没有对齐

分享按钮定宽 112rpx 而内容靠左，文字右边缘比上方电话图标和下方「预约看仓」的右边缘缩进约 25–30 逻辑像素（目测加比例换算，未精确测量）。「收藏」因此悬在行中间。建议内容右对齐。

### RC9-06（P3）近似仓小样是注入数据，不能算该状态通过

C03 标题显示「渲染测试 · 10m³需求」、仓位名 `TEST8`，是把视图模型注入页面实例得到的。Codex 在索引里如实写了，但 `self_check` 标 PASS 容易被读成状态通过。建议这类图标 `RENDER_ONLY`，真实路径的近似仓图在 01C 补。

### RC9-07（P3）新令牌没有进令牌文档

`--mk-color-overlay-photoLabel` 只加在 `tokens.wxss`，`docs/tokens/` 和 `05_Design_Tokens_Components.md` 里没有。另外它是纯黑 65%，现有遮罩令牌用的是带品牌墨色的 `rgba(31,42,36,…)`。保留原色值是合理的保守做法，是否统一色相留到 P5 总评。
