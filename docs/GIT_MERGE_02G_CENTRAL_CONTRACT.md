## 重要的“中央”边界（不得改写为已正式归并）

- **已接**：`app/index.html` 的统一 02G 中央评审入口 → 同一套演示 runtime（H01→CAP/S01/S02→S5/QUICK→O01）；`SIM_*` 来源的统一店、仓、报价与订单快照校验。
- **未接**：原中央历史页面使用 `app/data/mini_koala_data.js` / `store_master.json` 的 `MK_*` 商业 ID，存储价格口径及 `mini_storage_price_gate_v1.js` 的 legacy O01 报价模型。这是**不同数据契约**。两者尚无签收的 store/unit/size_option 对照表，不能把 `SIM_BJ01_U03` 编造成真实仓号或把演示折扣当旧中央月租价。
- **若遇旧 ID**：统一路由明确提示不可承接，不生成订单、不默认翻译、不套用旧快照。要进入真实中央数据链路，需先由中央批准一份 ID 对照与报价模型迁移裁决，再定向绑定。
- 预约仅生成本地线索，支付仅模拟；已冻结视觉仍需 S01/S02/S5 同门店同容量同租期的 375/390 终验。真实微信能力和后端不属于本阶段。
- 未修改 `main`；原 PR #11～#14 保留 Draft。本 PR 仍 Draft，Release Gate HOLD。
