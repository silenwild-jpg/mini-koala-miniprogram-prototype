## 1. 业务决策与时效定义

- 已成功创建的**待支付订单**拥有固定的 **3 小时（10,800 秒）支付有效期**。有效期从 **`createdAt`（订单成功创建时间）** 开始。
- 截止时间为 `expiresAt = createdAt + 10_800_000ms`，倒计时仅从这个绝对时间计算；刷新、重进首页、切换找仓视图、进入订单详情不会重新开始计时。
- **报价还未形成订单时**的五分钟报价有效期保持不变。不得误把 3 小时理解为报价有效期、租期、微信支付交易有效期或用户页面 Session 时长。
- 已有旧订单的 `expiresAt` 不应被新代码静默延长；三小时仅适用于新生成的订单。
- 原型暂按三小时持有演示预留库存；真实业务上线前必须由运营、交易后端确认三小时预留政策、库存利用率、支付平台订单失效时间与主动关单策略。

| 页面 / 状态 | 展示要求 | 主要按钮 |
|---|---|---|
| H01 待支付 | 店名 / 仓位；首次应付金额；**支付剩余 HH:MM:SS** | 继续支付 |
| O03 待支付订单详情 | 同一截止时间及同步倒计时；金额、订单状态 | 继续支付 |

| H01 / O03 倒计时归零 | **订单已超时**，不再显示可支付金额入口；旧订单信息只供查看 | 重新选择仓位 |
| 已成功支付 | 立即隐藏倒计时，转为入仓/身份验证任务 | 查看入仓准备 |

> **2026-11-11 最新业务裁定（已确认）：** 一次支付失败即终止该笔订单，状态改为 `payment_failed`，并立即释放预留仓位及解除未使用的锁定权益。用户仍可再次尝试租仓，但必须重新选仓、确认价格、生成新订单及新的三小时截止时间；不得复用失败旧单直接支付。用户主动关闭支付界面但未提交失败结果时，订单仍为 `pending`，三小时截止时间不重置。

## 3. 视觉层级与预警

- 倒计时属于 H01 待支付任务卡内部的**第二信息重点**，前面为「首次应付金额」，后面为主要 CTA。不新增浮层、第二张大卡、横幅、铃铛通知。
- 格式：`HH:MM:SS`（例如 `02:46:35`），使用等宽数字，变化时不发生文字抖动；只使用单行显示。
- 颜色阈值由真实剩余秒数决定：
  - `>30m`：正常绿色；
  - `<=30m 且 >5m`：橙色提醒；
  - `<=5m`：红色提醒；
  - `<=0`：过期状态，隐藏计时器。
- 不建议秒级闪烁、弹窗催付或高频声音提醒。计时器使用 `role=timer` 与 `aria-live=off`，避免读屏每秒报时。过期状态变化应有独立状态反馈。
- 375×812 和 390×844 均必须检查一行完整显示、主按钮 44px 以上热区、金额大数值不挤压倒计时。

## 4. 订单业务处理契约

1. 提交 O01 / QUICK 并成功生成订单时，产生只增一次的 `createdAt` / `expiresAt`。
2. 订单未付款时预留可租仓位，剩余时间由共享数据快照计算。页面后台暂停计时并不影响截止时间。
3. 截止时业务引擎将 `pending → expired`；释放预留库存与未使用的锁定权益，废弃原报价与当前库存资格。
4. 支付尝试失败即终止当前订单、立即释放预留仓位；**再次尝试**必须像超时订单一样重新创建订单，不恢复原订单支付权限。
5. 过期旧单禁止直接继续支付；H01 / O03 的重下单动作进入 QUICK，清理 QUICK 上一次的 UI 选仓结果，要求重新选择并确认当前可租仓位、实时价格、起租日期和付款条件；保留已有订单历史。
6. 重新发起会建立**新订单 ID、一次新的付款截止时间**，不会延长旧订单或给原订单恢复可支付状态。
7. 页面仅展示截止时间；正式支付权限、超时校验、库存释放以及回调竞态必须由后端执行。小程序 JS 时间不具备交易授权可信度。
