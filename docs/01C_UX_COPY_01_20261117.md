## 文案对照

| 范围 | 修改前 | 普通模式 |
|---|---|---|
| 提交中 | 正在提交，请稍候 | 正在提交，请稍候 |
| 可重试失败 | 本次模拟提交未完成，输入已保留… | 暂时无法提交，请重试或返回修改 |
| 结果未知 | 尚未取得确认结果，请核对结果；不会另建一条需求 | 提交结果暂未确认，请勿重复提交；按钮仍为核对提交结果 |
| 保存失败 | 本机保存失败… | 暂时无法保存，请保留已填写内容并重试；保留刷新或离开可能丢失内容的实际限制 |
| 恢复填写 | 已恢复上次输入… | 已恢复上次填写的信息，请核对后继续 |
| 预约/顾问成功 | 资料已保存在本机，尚未发送给顾问 | 预约需求已保存 / 咨询需求已保存；可在“我的需求”中查看 |
| 企业首次/更新 | 企业需求已保存，展示B2B_LEAD内部编号 | 企业需求已保存 / 企业需求已更新；普通模式不展示内部ID |
| 退款失败 | 演示候选，待产品签收；未发起真实退款 | 退款处理暂未完成，请查看后续进度 |
| 发票失败 | 开票失败…不代表实际开票成功 | 开票暂未成功，请核对资料后重试；原申请记录已保留 |
| 发票重试 | 更正资料后重试 | 更正资料后重新提交 |
| 发票内部说明 | 以上为待签收演示状态，真实开票由服务端办理 | 仅在review=1显示 |

“提交成功”可能被理解为顾问服务已收到。当前实际完成的是需求记录保存，因此成功提示使用“已保存／已更新”，不承诺真实发送、联系时间或服务结果。顾问表单说明保留联系电话必填、地址选填，移除未实现的顾问将联系等承诺。

## 模式边界

普通模式保留原有字段、按钮、错误恢复、原ID更新和明确新建流程；无故障注入菜单、内部状态名、模拟账本或签收说明。中央已有“内部演示设置”仅在review=1显示，没有新增页面或入口。

企业需求重新打开时，按既有UNKNOWN_RESULT恢复提交与输入框的禁用状态，避免提示与控件矛盾；核对结果仍使用原请求键，状态转换未改。

企业页明确新建时保留当前review=1标记，避免URL失去评审模式但页面仍显示评审控件；没有改变业务导航入口或新建记录规则。

评审模式使用同一用户操作界面，原有故障切换继续可用，在既有评审说明中显示状态名及本机模拟边界；退款失败/恢复和开票结果切换继续只在评审模式提供。普通用户仍不能确认退款完成、验仓通过或实际开票成功。review参数不是生产鉴权。
