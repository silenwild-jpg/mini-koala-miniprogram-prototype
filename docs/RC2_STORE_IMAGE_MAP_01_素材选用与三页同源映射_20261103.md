# RC2-STORE-IMAGE-MAP-01｜门店照片精修与三页同源映射

**项目定位：** 迷你考拉仓微信小程序高保真内部演示；非真实门店图片证明或正式上线。

**父基线：** [PR #56](https://github.com/silenwild-jpg/mini-koala-miniprogram-prototype/pull/56)，Commit `f6c8a15ffffada8aa0665c979d91c05b05f0aa96`。原 RC2 私有站不自动更新，`main` 不归并。

## 1. 收到的原始素材与裁定

- 用户提供《门店照片.zip》，收到14张JPEG。经视觉复核，选用12张不同取景的门店环境照片；2张为高度相似原图 / 水印图，作为保留素材不在门店卡使用。
- 图片均由原图经EXIF转正、中心偏置裁剪、轻度亮度/对比度/色彩统一、WebP压缩得到，未生成虚构场景，未增删对象。
- **全部12个演示门店ID的物理照片来源未核实**。固定映射是 `SIM_*` 演示候选上的图位分配，不意味着这张照片摄于对应地理位置/门店。正式上线需运营/门店侧核对。不得以演示照片作实景位置、设施或库存的独立证明。

## 2. 三页的同源契约

- H01：首页横滑门店卡读取 `SIM_FIXTURES.stores[].photo`。保留用户批准 VIS-11J 冻结英雄图、场景图、导航图；只更新运行态门店卡的照片。
- S01：唯一 R2 门店卡显示同一 `store_id` 的 `card.webp`，不再按索引在两张通用素材间轮换。地址/服务标签仍以 `SIM_FIXTURES` 为唯一业务源。
- S02：同一 `store_id` 使用对应 `hero.webp`；当前仅确认一张环境源图，因此隐藏无意义的 `1/1` 轮播按钮，不把其他店的照片伪装为同店相册。
- `photoLegacy` 保留旧图，仅在图片文件不可用时触发回退；当实际资源被装入 ZIP 时应全部读取新图，无404。

## 3. 物理文件与数据变更

- 新增 `app/prototype/parallel/core-journey-fix-01/demo/assets/store-curated/v1/SIM_*/card.webp`（512×512）与 `hero.webp`（1152×720），共24个WebP。新图总大小约0.835MB。
- 新增 `.../store-curated/v1/mapping_manifest.json`，包含源图原始SHA256、裁剪坐标、所有衍生品哈希、演示门店ID、照片归属状态。
- 改 `fixtures.js`：只添加图片路径及 provenance 元数据；不改店名、地址、距离、价格、库存、推荐、订单和真实仓位 ID。
- 改 `home-bridge.js`, `s01-r2-content.js`, `s01-r2-bind.js`, `app.js`：只调整图片路径、文案及 S02 单张图片的无效轮播按钮，符合VIS-GUARD定向补图要求。

## 4. 验收

- Node 来源一致性：12个门店ID、24张图、每张文件哈希、每个路径均核对PASS。
- CI 375×812、390×844：应逐页验证 H01/S01/S02 加载正确、对应相同门店ID、图片无404、既有S01四导航/三筛选和订单回归仍成功。
- S01最终获批整页原图仍未物理收到，不能把照片更新视为全页视觉终签。
- 登录与真实支付仅演示，真实微信、真实门店照片对应、国家地理/距离精确性仍需另验。

## 5. 签收边界

**当前是演示照片映射候选**。照片可用于内部 UX/视觉评审，并且允许日后逐门店替换为真实照片；正式门店照片的同店实拍归属和图片授权状态需另行核验。当前 RC2 站点未自动部署，需试用者授权后独立发布新候选。
