## 目的和边界
仅比较两处视觉布局：S01 的“未选/已选需求”状态操作条，以及匹配模式中“实际仓位容量、整期租金、月租构成、立即下单”组合。冻结的 S01 结构（排序/距离/服务；二级特价仓与送搬运；第三固定考拉E存；第四位后紧凑实体门店；整卡进入S02；下单进入O01）、H01 和 S5 母版、容量租期同时确认、1–60个月显式租期、价格计算均不变。

隔离实现：仅顶层 URL 显式追加 `&s01_ux_refine=A` 或 `&s01_ux_refine=B` 时加载探索 CSS 并调整 S01 局部 DOM，无参数时 PR99 原母版保持原视觉。仅测试，不发布。

## 两方案定义

**A｜平面紧凑双层（推荐）**
- 未选：`不知道租多大？` + `估算一下 ›`，已选：`需求 3m³ · 12个月` + `修改 ›`。
- 状态栏 44px；无附加边框、卡片或多余解释。
- 匹配仓位上行：`仓位 3.5m³ · 适合家庭用品`。
- 匹配仓位下行：左侧整期主价 + `¥260/月 × 12个月`，右侧 90×48px 立即下单按钮。
- 保留匹配态的整期主价格与分解，不显示公开立方单价。

**B｜两行状态摘要 + 全宽操作（对照）**
- 未选：“不确定容量 / 先估算需要多大空间” + “估算一下”；已选：“已选需求 / 3m³ · 12个月” + “修改”。
- 状态栏 58px；仓位容量/用途、价格构成、全宽48px立即下单按钮分别占一层。
- 购买按钮强调更强，但每家实体门店卡明显变高。

## 裁定建议

**建议方案 A 进入下一轮母版候选，而 B 保留在隔离探索分支作为反证。** A 的价格区宽度、仓位信息层级和按钮可触达尺寸满足要求；前两张匹配实体门店卡节约约108px垂直空间，375px首屏更容易看到第三位考拉E存或更多后续信息。B 的全宽按钮更醒目，但以显著降低列表密度为代价，不匹配 S01 的“先浏览多家，再选择仓位”任务属性，更适合订单确认页而非门店列表页。

建议保留进一步可优化点：A 中“需求 3m³ · 12个月”与“仓位 3.5m³”应持续区别用户需求和实际可租仓型；长金额超过真实模拟极值时需另测一组极端金额字体与可访问性，方可做正式冻结。需在人眼确认 A 在真实微信 WebView 的指尖点击状态、焦点反馈、不同门店图片后再准入。
