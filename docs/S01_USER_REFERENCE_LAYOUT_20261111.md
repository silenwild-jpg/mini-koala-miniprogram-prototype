## 1. 选定的信息结构

仅适用于 S01 **已确认容量与租期后的前两家实体门店展开卡**：

| 区块 | 内容（已有字段，不新增） | 相对信息位置 |
| --- | --- | --- |
| 上层门店头部左侧 | 门店实景图片 | 左侧方图 |
| 上层门店头部右侧 | 门店名称 → 促销/服务/属性标签 → 单行地址（超长截断） → 距离 | 垂直阅读，自上而下；右上弱箭头可进入S02 |
| 下层左侧 | **仓位容量**（加粗绿色）+ 适用物品短句（小字） | 主次两行 |
| 下层中间 | **整期租金** + 轻量租期折扣；下一行 **￥整数月租/月 × N个月** | 与容量平齐，整期价第一视觉重点 |
| 下层右侧 | **仓号 A001–D030** 浅灰小标签 + 「立即下单」48px按钮 | 仓号在上、操作在下 |
| 下层分隔 | 店信息与仓位横向区域之间细分割线；容量与价格之间弱竖线 | 仅作信息分组，不生成卡套卡 |

**所选布局不能误读为业务价格政策变化**：用户截图中的金额仅作为展示效果，实际从 `core.amounts()` 获取整数整期租金、整数折后月租、已选1–60个月及合法的租期折扣标签。

## 2. 显示条件与交互合同

- 未同时确认容量与租期 → 全部实体门店仍是**同一种紧凑卡**，没有仓号、具体匹配仓位和「立即下单」。
- 已确认完整需求 → 前两家门店各展示一个适配仓位、同一内部 `unit.id` 的仓号/容量/价格/用途；第三位依旧考拉E存；第四家以后保持紧凑卡。
- 门店头部/箭头进入 S02，右下「立即下单」继续传 `unit.id` 至 O01，禁止因调整按钮容器造成冒泡误点。
- H01第三张灵活运营位、S5两家加E存、S02完整仓位信息以及对应跨页同号保持原规则。
- 门店标签按全局规则：有效促销为第一，暖色；后续服务、属性弱灰边框。**图片中的绿色标签仅是参考图表现，不回滚已批准全局语义色规则**。
- 允许重排内部图片、间距、按钮比例，但不得丢失信息、展示虚假原价、引入「月均」「月均约」、额外「查看门店」文字按钮或对比功能。
- 极端长金额或很长用途文字若出现不适配，应调整响应布局而不是截断整期价格、折扣或月租×月份计算式。
