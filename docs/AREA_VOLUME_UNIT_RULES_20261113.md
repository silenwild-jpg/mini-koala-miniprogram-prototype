# ㎡ / m³ 双单位规则｜历史决策追溯与当前基线

决策来源：用户2026-11-12明确接受双单位策略。此前“本轮未找到完整规则”的判断现已由历史对话追溯修正。

## 已批准规则
1. m³是业务标准容量单位。
2. 用户可在㎡与m³之间切换输入/查看；双单位是同一仓储空间的表达方式，不建立独立的平方米计价体系。
3. 按仓位实际尺寸和实际有效高度进行面积/体积换算；不得无条件将㎡与m³按固定系数等价。
4. 2.5m高度只适用于标准仓；其他仓型必须使用其实际高度，不得把2.5m套用到所有仓。
5. 保留用户原始输入单位和数值，同时保存换算后的标准容量值，便于跨页回填、匹配和解释。
6. 单位切换不改变同一仓位的报价，不产生㎡独立计价。
7. 无法获得可靠仓高/尺寸而无法准确换算时，不得伪造精确换算值或擅自四舍五入；保留原始输入并提示补充实际尺寸/选择标准仓型。
8. 单位切换不得丢失原始输入、容量需求、租期确认状态或报价上下文。

## 计算契约
- 业务标准容量：m³。
- 几何关系：仅在已知有效底面积与对应仓位有效高度时，按体积=底面积×有效高度进行换算。
- ㎡输入必须明确其代表的底面积/占地面积；若用户说的是建筑面积、房间面积或其他口径，不能默认等于仓位可用底面积。
- 仓高需关联具体仓型/仓位数据；2.5m仅为标准仓高度，不是全局常量。
- 匹配与推荐统一使用标准m³容量，不得让前端不同单位各自生成独立筛选口径。
- 报价始终以仓位/租期及统一价格快照为依据，单位只是容量表达层。

## 验收
- m³输入→切换㎡→切回m³，原值与换算值稳定。
- ㎡输入→使用实际高度换算；标准仓可使用2.5m，非标准仓使用其自身高度。
- 缺少有效高度时，不生成虚假精确值、不丢失原始输入。
- 单位切换前后，同一仓位、同一租期报价完全一致。
- CAP→S5→S01→返回CAP，原始单位、原始值、标准容量、租期状态一致。
- 不新增㎡独立价格、不改变容量和租期必选门禁。
