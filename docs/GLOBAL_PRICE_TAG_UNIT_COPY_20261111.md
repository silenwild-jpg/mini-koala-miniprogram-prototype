## 1. GLOBAL-PRICE-INT-01｜全部人民币价格为整数（ACCEPTED / 最高优先）

1. **业务真实口径是整元价格**。对演示数据、计算中间值或旧 UI 遗留的非整数人民币金额，**直接截断小数部分**，不四舍五入、不向上取整，也不显示 `.0`、`.00`、`.5`；例：`¥62.56 → ¥62`、`¥240.50 → ¥240`。除明确退款/负金额的特殊情形，非负价格使用 `Math.trunc` 即可。
2. **全站金额展示范围**：H01、S01、S02、S5、容量/物品估算、快捷下单、O01、O03、订单列表、支付结果、押金、管理费、优惠券、退款及租后金额，均使用同一整数价格规则。容量 `3.5m³`、距离 `1.2km`、优惠 `6.5折` **不是人民币金额**，允许小数。
3. **保留已确认的两行价格结构，不得另起口吻**：第一行 `¥3,120`（仓位整期租金），第二行 `¥260/月 × 12个月`。绝对禁止 `月均`、`月均约`、`平均每月` 及这一类面向用户的表述；不可改成「月均¥260 · 12个月」。显示 `×N个月` 必须能够在人民币元级**精确等于**整期租金。
4. **数据与展示口径必须相同**：真实/演示底层应在唯一权威价格层形成整数**折后月租**，同一选中仓位的整期租金 = 整数折后月租 × 已确认租期月份；组合仓整期租金 = 所选各仓位整数折后月租合计 × 月份；押金为已批准的一个月折后月租；管理费按整单¥50。避免仅把显示的 `240.5` 截成 `240`，却继续使用旧整期金额 `2,886`，造成 `240 × 12 ≠ 2,886` 的显示冲突。**这是代码接线验收条件，不是此次文档编写已完成的改造**。
5. 浏览态 `¥/m³/月起` 单价含有容量除法；即使原始租金为整数，计算仍可能产生分数。界面展示按本规则**截断小数**，但最低价来源、固定参考租期、可售资格与店内比较范围应继续保留业务依据，不得将不同租期口径混淆。演示页面可以使用演示数据，不必冒充真实客户交易价格。
6. `O01` 订单金额组成与单项整数必须核对：押金、整期租金、已批准优惠抵扣、管理费、应付总额整数相加一致，退款/续租也应同源。用户此处已确定「整元计价」，**无需再提出舍入策略等待批准**；实现者仅需验证计算层已按整元执行。
7. **无默认12个月**：浏览态的历史12个月公示计算期，不代表用户选择的租期；正式匹配与两行整期价格只在有效容量和1–60个月显式选择完整需求后出现。
8. 禁止在新的页面、设计稿、文案规范、测试用例中重新引入 `月均`、`月均约`、`四舍五入`、`向上取整` 作为未来规则；历史文档如果保留旧字句，必须显著标记已被本条取代。

**实现时重点查验**：`presentation-policy.js` 当前 `money` 允许 `maximumFractionDigits:2`，`cubicReference()` 用 `toFixed(2)`；`br03-policy.js` 及 `br04/bridge.js` 仍有历史展示文案；`demo-core.js` 的核心报价需原子调整并补测试，不应只修显示。

## 2. GLOBAL-STORE-TAG-01｜门店标签全局同源/同序（ACCEPTED）

**已确定**：同一家门店，在同一个用户状态和活动条件下，H01 首页门店卡、S01附近门店、S02门店详情、S5推荐门店的有效标签必须有**同样的内容和相对顺序**。页面只控制可见上限，不能每页自造标签、修改文案或重新排序。

标签模型建议 `{tagId, label, type, rank, active, conditions}`，并由一个共享组件/规则返回有序数组：

| 顺序 | 类型 | 示例 | 颜色及视觉层级 |
|---|---|---|---|
| 1 | **promotion/促销** | 特价仓、真实生效的限时活动 | 每店有效时**最多1枚**、优先排首；暖橙/珊瑚橙浅底和较深暖色文字，克制但比服务标签更醒目 |
| 2 | **service/服务** | 免费搬运、近地铁、停车便利、小推车 | 灰绿文字、浅灰描边、白底/极浅灰底 |
| 3 | **attribute/门店属性** | 新开门店、24小时存取、电梯直达、全天监控、控温防潮 | 同服务标签的低对比描边样式，语义保持稳定 |

- **关键例外**：没有有效促销时，不造一个促销标签占首位；第一枚直接是服务/属性标签，仍用弱化中性色。不能把「新开门店」「免费搬运」全部无差别当成促销：**免费搬运是服务权益**，新开门店是属性，只有明确促销资格时才能落入促销类。
- 同级顺序建议：服务优先 `免费搬运 → 近地铁 → 24小时存取 → 电梯直达 → 停车便利 → 小推车`；属性随后 `新开门店 → 全天监控 → 控温防潮`。这一同级顺序是本轮设计审查**建议**，需在 VIS-SYSTEM-01 最终确认并使用一个权威 rank 表；不能临时按页面重新排列。
- 数量上限：**H01至多2个；S01紧凑至多2个、展开态至多3个；S02允许4–5个；S5建议2个**。不足时只展示有资格的实际标签，不凑数。仓位的 `6.5折` 价格系数标签**不占门店服务标签数**。
- 按钮视觉禁止复用促销标签语义。所有标签字号、内边距、圆角、边框、色板、显示溢出交由 VIS-SYSTEM-01 全局 token 冻结。本轮确定**色彩层级方向**，不是宣称像素样式已经归并。
- **当前代码偏差**：`fixtures.js` 有 `operatingTag` 和 `serviceTags`，同时 `tags` 拼接，类型并不严格；`home-bridge.js` 只取 `presentation.services()` 的服务标签；`s01-r2-content.js` 只给 `services`；`s01-r2-bind.js` 绘制这些服务文本；`br04/bridge.js` 和 S02 又各有独立入口。**已明确业务规则≠代码已完成统一**。必须集中新增单一标签选择器，再让 H01/S01/S02/S5 按同一个排序结果各取前 N。
- **测试门禁**：同一门店在四页出现的前 N 个标签必须等于同一有序数组的切片；促销过期/无促销/同时有促销与服务/服务不足/五城/S01筛选后/E存服务位例外均需覆盖。

## 3. GLOBAL-UNIT-COPY-01｜仓位适用文案同源、容量分档（PROPOSED，待文案签收）

审查发现三套入口：`app.js` 的局部 `usage(u)`、S01 `u.volume<=3/6` 分段、`br03-policy.js` 的 `generic(volume,page)`；S5 又通过 `s5SharedUnit()` 的 `P.describe(...,'S01')` 取文案，仍有页面状态前缀 `容量匹配 · `。同容量可能出现不一致的「适合……」。

**建议统一一套与显示页面无关的基础文案，再按界面槽位截取**，不把容量匹配结论写进物品清单。容量/场景只是便于理解的示例，不代表不考虑仓内门洞、层高、堆叠、安全与实际尺寸即可保证装下。

| 实际仓位容量 | 建议核心短句（可同源复用） | S02 / 容量页扩展说明方向 |
|---|---|---|
| 0.5–1.5m³ | 行李箱、换季衣物 | 纸箱、文件和随身闲置物 |
| >1.5–5m³ | 纸箱、箱包、小件家具 | 收纳箱、折叠椅、边几 |

| >25–50m³ | 大件家具、家电 | 多件家庭家具、搬家物品 |
| >50m³ | 大批家具、物资 | 大型家庭储物及商用物资 |

- S01展开卡：优先**7–12字左右**，比如 `适合纸箱、小件家具`，省略不增加独立说明行。S5建议同短句；S02可支持两项场景/物品短行；H01纯门店推荐卡**原则上不强塞仓位适用说明**；容量页可提供图文展开和可调物品估算。
- 同容量所有页面使用同一个类别映射；如果客户按物品估算，则另有具体物品清单来源，但不应把自动算出的「适合」文案伪装成已经校验具体家具能装下。
- **分档边界**：0.5–1.5；(1.5,5]；(5,10]；(10,25]；(25,50]；>50 m³；1–60月租期不影响容量适用文案。组合仓要另行标明多舱组合，不直接按总容积承诺某一单件大件能放入。

## 4. S01前两张匹配仓位卡布局再评估（非结构回退）

**信息维持冻结**：仓号、容量、用途、整期价格、折扣、折后月租×租期、立即下单。当前采用「容量信息行 + 价格和按钮行」；当用途文案不够短、仓号占位、主价较长时，375px 下第一行挤压，整期价又和折扣标签/48px按钮争夺横向宽度。可优化**现有区域内部对齐与留白**，不增加新卡片，**不退回拥挤三列旧结构**。

| 方案 | 层级 | 优点 | 风险与裁定 |
|---|---|---|---|
| **A推荐：左右分组、两层价格** | 第一行仓号轻标签+容量大字+单行用途；第二行左侧整期价+折扣，下行月租×租期，右侧48px下单 | 维持已签收信息结构，操作稳定，最小变更 | 首行需给用途足够弹性空间；极值金额场景须核对价格是否溢出 |
| B：两行价格独占宽 | 第一行仓号与容量；第二行整期价+折扣及副价；第三行整宽下单 | 长价/长用途健壮 | 拉高第一、二张门店卡，削减首屏可见内容，优先级低 |
| C：价格主视觉浮靠右、仓号/容量靠左 | 单行尽可能收纳仓号、容量、金额、动作 | 看似紧凑 | 易退回旧三列拥挤问题，**不推荐** |

**优先方向**：保留A作为视觉试验母版，先优化仓号轻标签的占宽、容量字号、用途单行省略、价格与按钮垂直对齐和卡片底部间距；不再新加「查看门店」、对比或仓位背景容器。用375×812/390×844的实际原型，至少覆盖最短租期、60个月、超长金额、长用途、促销有无、两卡并存与第四位紧凑卡连续滚动后，再人工裁定 CSS。
