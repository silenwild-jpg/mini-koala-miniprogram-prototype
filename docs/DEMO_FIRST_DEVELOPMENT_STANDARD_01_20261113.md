# DEMO-FIRST-01｜产品演示优先开发标准

生效日期：2026-11-13  
适用范围：迷你考拉仓小程序原型、前端视觉与交互迭代、跨页面流程、演示验收及后续后端交接。  
状态：项目级默认规范；后续任务如无明确例外，按本规范执行。

## 1. 核心原则

当前阶段的首要交付目标是：**让评审者能够沿真实用户的使用路径，完整体验界面、信息、状态和交互。**

当前不是生产数据真实性验收，也不是后端业务规则最终定稿阶段。凡是不影响前端体验完整性的真实数据、业务规则、接口和权限问题，不得自动升级为前端阻塞项。

数据缺失或业务规则未确认，不应成为空白页面、断裂流程、缺少状态、无法操作或取消必要视觉呈现的理由。

## 2. 前端必须优先完成的内容

以下事项属于当前阶段的前端交付范围，不能以“等待真实数据/后端规则”为由省略：

1. **真实用户路径**：从入口、需求填写、门店/仓位浏览、推荐、报价、预约/下单、订单结果到后续服务，路径可连续体验。
2. **界面状态完整**：默认态、选中态、未填写态、加载/空态、无匹配、库存不足、异常提示、成功/失败/取消、返回修改等与当前页面相关的状态均有可评审呈现。
3. **交互可执行**：按钮、筛选、切换、表单、弹层、返回、编辑、确认等主要操作必须产生符合预期的界面反馈；不得只做静态截图式页面。
4. **跨页状态一致**：用户已输入的容量、单位、租期、城市、门店、仓位、订单上下文等，应按已冻结的产品规则正确传递、回显和修改。
5. **演示数据完整**：可使用合理的模拟门店、仓位、价格、距离、库存、促销、评价、服务时间和订单数据支撑页面与流程；数据应前后一致，能够覆盖关键场景。
6. **视觉表达完整**：不得因为数据暂缺而删除已经确定的模块、标签、价格结构、活动状态或必要信息层级。需要时用可控演示数据填充。
7. **失败路径可体验**：对于暂未接入的外部服务，可通过前端可控的演示响应覆盖成功、失败、取消、重试和返回等路径。

## 3. 可以后置到后端开发阶段的事项

下列事项如不妨碍前端状态和交互演示，应单独登记，不阻断前端开发：

- 真实门店、仓位、库存及实时可售状态；
- 真实价格、折扣档位、促销适用范围、优惠叠加与结算细则；
- 送搬运、送租期、优惠券、人工赠期等活动资格和授权规则；
- 实际距离、地图坐标、导航路线、地理围栏及地图服务校验；
- 手机号、支付、订单、退款、押金、发票、合同和协议的真实接口；
- 真实评价、服务设施、门店营业时间和其他尚未确认的门店资料；
- 数据权限、风控、接口鉴权、生产环境异常处理及运营后台配置。

后置不等于忽略：必须进入待确认清单，写清楚缺失内容、影响页面/流程、需要确认的业务或后端责任方，以及预计确认阶段。

## 4. 演示数据与规则的使用要求

1. 允许构造模拟数据与演示规则，用于完成用户可见的界面、状态和流程。
2. 模拟数据应集中维护在 fixture、demo config、mock adapter 或等效数据层，不得散落硬编码在多个页面中。
3. 同一实体跨首页、附近门店、门店详情、推荐、报价、下单和订单页时，名称、图片、仓位、价格、标签、状态及上下文应保持一致。
4. 模拟规则应能确定性复现，支持切换关键状态；不得依赖随机刷新导致页面前后矛盾。
5. 可以模拟活动资格和结果，以呈现特价仓、租期折扣、送搬运、送租期、优惠券等完整视觉状态；但需将尚未确认的资格、叠加、适用范围和结算细则记录到后端待确认清单。
6. 不得把未经确认的模拟规则写成已冻结的生产业务规则；不得因后端未确认而把演示模块直接删除或长期隐藏。
7. 面向用户的界面不应出现“模拟数据”“演示数据”“测试数据”等破坏体验的解释性文字，除非用户明确要求在特定评审环境展示标识。内部数据配置和交接文档应保留模拟来源说明。
8. 当某个模拟值可能被误认为已确认的生产承诺（例如真实优惠金额、库存承诺、服务资格）时，内部清单必须标记其模拟属性和待确认事项；前端仍应完成该状态的体验呈现。

## 5. 问题分级与阻断规则

| 类别 | 例子 | 当前处理 |
|---|---|---|
| 前端体验缺陷 | 页面缺失、流程断裂、按钮无反馈、状态无法进入、跨页数据丢失 | 当前修复，必要时阻断验收 |
| 视觉/信息缺陷 | 已确认模块缺失、层级错误、文案/标签错位、页面结构偏离母版 | 当前修复 |
| 演示数据缺口 | 缺少某种门店、仓位、促销或订单样本 | 补充模拟数据，继续演示 |
| 待确认业务规则 | 活动门槛、折扣范围、赠送条件、优惠叠加方式未定 | 采用明确标记的临时演示规则完成前端，登记后端确认项 |
| 后端/外部依赖 | 地图、支付、手机号、实时库存接口未接入 | 用可控适配层/模拟响应完成前端路径，登记接入任务 |
| 生产真实性风险 | 模拟信息可能被当作真实承诺 | 不把它当作生产事实；内部登记风险与替换条件，不以此为由删掉演示体验 |

**只有会导致用户路径不可用、已冻结产品规则被破坏、数据上下文无法正确传递，或形成明显误导性前端行为的问题，才作为当前前端阻断项。** 单纯缺少真实数据或后端最终规则，不构成阻断理由。

## 6. 每个迭代任务的交付要求

每次涉及页面或流程的开发/评审，至少输出：

1. **前端本轮完成**：已实现的页面、状态、交互和跨页链路。
2. **演示数据与临时规则**：哪些内容使用了模拟数据，覆盖了哪些场景；不需要在用户界面暴露模拟说明。
3. **待业务确认**：未定规则、需要业务决策的问题及其影响。
4. **待后端接入/确认**：真实数据源、接口、权限、计算或外部服务的接入事项。
5. **当前阻断项**：仅列真实阻碍前端体验或违反冻结规则的问题。
6. **验收证据**：关键用户路径与状态的运行截图/录屏、测试结果；不能把静态代码检查等同于浏览器运行验收。

待确认清单建议字段：
- 编号
- 页面/流程
- 待确认数据或规则
- 当前演示处理
- 业务影响
- 需确认责任方（业务/运营/产品/后端/第三方）
- 后端接入或确认阶段
- 状态

## 7. 验收口径

当前版本优先验收“演示体验是否完整”，具体检查：

- 评审者能否从入口独立完成关键用户任务；
- 所有重要页面是否有完整且合理的内容，不因真实数据缺失出现空白；
- 主要状态能否通过可控方式进入并正确展示；
- 关键交互是否可操作，前后页面是否一致；
- 模拟数据是否稳定、连贯、可复现；
- 临时业务规则与真实生产规则是否明确分层，并有单独待确认记录；
- 后端未接入事项是否有明确交接，不影响本轮前端验收结论。

**本阶段不以真实数据接通率或生产规则定稿率作为前端演示完整性的替代指标。** 后端真实接入后，再按确认后的数据、规则和接口进行替换、联调与生产级验收。

## 8. 对后续任务指令的默认解释

当用户说“继续”“执行下一步”“优化页面”“完成验收”时，默认：
- 先确保用户路径、界面状态、视觉模块和交互体验完整；
- 遇到数据缺失时优先补充一致的演示数据；
- 遇到规则未确认时采用可替换的临时演示规则，并记录待确认项；
- 不擅自把后端待确认项升级为前端阻断；
- 不把演示用模拟规则写入生产规则基线；
- 不因等待后端而停止可独立完成的前端工作。

---
本规范与现有已冻结的产品规则、视觉母版和交互契约共同生效。若出现冲突，已明确冻结的产品决定优先；未冻结的业务细则按本规范暂用可替换演示规则，并进入待确认清单。
