# S01-UX-REVIEW-03｜九状态边界、紧凑卡视觉与RC2单一候选归并准备

审计日期：2026-11-04。范围：仅 S01 相关结构、业务状态与和 S02/S5 的契约；非正式上线。

## 已确认的最新产品裁定

1. S01 视觉表层保留城市＋门店搜索、已选需求、**排序／距离／服务**三项筛选、特价仓／送搬运／只看单仓、四个底部导航。
2. 排序/搜索/筛选后按当前列表顺序 **前两家展开完整仓位信息，第三家及以后为紧凑列表行**；紧凑卡整行直接进入同 ID 的 S02，不能展开或在卡内直接下单。
3. 缺少可信定位时原型仍展示稳定演示公里数，同一数值用于显示/排序/距离筛选；不得把演示公里数标记成已验证定位。
4. 未验证手机号可以浏览公开起价和门店；正式整期报价/订单执行手机门禁。仅有容量需求而租期待选的状态不得发正式价。
5. 容量>10m³ **或**整期租金>¥2000 触发一次顾问入口，不能每家门店重复提示；不以未经手机号验证的正式报价文案暴露价格。
6. E存/顾问与修改需求用于全城无合适容量；组合与近似容量不能伪装成单仓完全匹配，近似容量不允许从 S01 直接下单。

## A. 九类状态机器与实际回归

以下将主业务匹配与跨维覆盖分开，不把“九类”误写为九个互斥 tab。全部以同一构建、375×812/390×844 的真实 Chromium 访问与截图检查，状态输入和渲染使用中央 core/fixtures。

| 状态 | 输入/边界 | 必须检查的结构与动作 |
|---|---|---|
| M0 未带需求 | `noDemand` | 展示公开价格和默认推荐，无手机号强制弹窗 |
| M1 需求匹配 | `normal` 3.5m³ / 6月 | 单仓真实库存可下单；整期报价仍受手机号约束 |
| M2 组合仓 | `combo` 9m³ / 6月 | 组合仓说明；不得把组合仓伪装成单仓下单 |
| M3 容量略小 | 14m³，隔离门店仅留12m³可用 | `near`、明确容量略小，“查看门店”不是“立即下单” |
| M4 全城扩围 | 满足容量的门店公里数全部改为≥5km | `expandedSearch`、匹配结果与显示距离一致 |
| M5 全城无匹配 | `noMatch` 200m³ / 6月 | `noAdequateMatch`；考拉E存／修改需求恢复动作 |
| M6 租期待选 | `noTerm` 3.5m³ | 不展示正式整期价；需求可编辑 |
| M7 库存突变 | `normal`后将特定门店可用仓全部置不可租 | `stockChanged`；无可下单仓位，状态回流 |
| M8 顾问阈值 | 12m³／6月 与 3.5m³／60月两条路径 | 大容量或高金额条件满足时，全列表**仅一个**顾问入口；进入预约/顾问链路 |

附加检查：前两家完整 / 第三家起紧凑；第三家 store ID 进入同 ID S02；查看更多、搜索清空、服务多选、城市切换、底栏停靠、售价、取消授权、订单/支付/失败/取消恢复。

## B. 紧凑卡人工截图复核（非用户视觉最终签收）

已实际逐图检查 S01 `02-third-card-375/390.png` 和 `03-tail-cards-375/390.png`，而非只看原有首屏截图。

- **结构符合**：第三家以后统一为「实拍来源/同门店图片，名称，两个标签，地址与公里数，一行可租容量提示」；没有任何展开仓位/单仓下单 UI。卡片点击直接进 S02。
- **视觉定向修复**：删除紧凑行继承的大面积阴影及胶囊式独立卡观感，改为清晰列表分隔；中文地址/距离/匹配摘要从 11px 调至 12px，限制地址为一行并保留右侧距离。前两张完整门店卡 CSS 未授权变更为零。
- **尺寸**：原截图（微调前）第三家卡高度约115px@375、120px@390（页面有等比缩放），图片约92px@375、96px@390，约等于 88px 设计基准；本轮微调后用最终 SHA 截图重新查看。
- **发现的额外缺口**：M8 顾问阈值起初只记录为业务状态，但组合仓卡片优先展示组合说明，顾问入口未必露出；现已用同一结果行中的单个“顾问选仓”动作修复，不额外新增信息卡。
- **仍存在的体验风险**：M5 全城无匹配时，前两家继续使用大图完整店卡但无仓位，首屏信息效率偏低。是否让特殊异常态全员紧凑，属于对“前两家完整”例外的结构决定，**本 PR 不擅自改变母版**。须后续业务/用户裁定。
- **原图准入**：未获得 S01 最新批准完整同状态原图的可核验 SHA，也未进行获批整页逐像素对齐，故只作本次**真实截图定向人工复核**；不可宣称历史母版 VIS_SIGNED PASS。
