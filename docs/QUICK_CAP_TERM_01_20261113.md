# QUICK-CAP-TERM-01｜快捷下单容量/租期与预约选填规则校正

**日期**：2026-11-13  
**实施范围**：当前RC2 HTML/Web原型；不等于微信原生、真实下单和CRM上线。

## 最新业务裁定（覆盖此前不正确的自动容量建议）
1. **QUICK快捷下单：需求容量和租期必须由用户主动确定**。从首页/底栏无需求直接进入QUICK时，选择门店或仓位不能自动替用户确认`requirement.capacity_m3`。QUICK页面内必须有容量选择入口；支持1、3、8、15、30m³快捷选择及0.5m³递增自定义（0.5–200m³），与现有中央需求合同共用数据结构。
2. **QUICK的容量、租期可以独立按任意顺序选择**，但在缺少容量时点租期需有清晰提示；仓位不足容量不得算匹配；容量变更须使旧报价失效，并在不再匹配时清除当前选仓。
3. **已由CAP/ITEMS明确确认的容量/租期在QUICK继承**，不重复强迫选择；用户主动修改其中一项时更新中央合同，并遵循价格/库存回归。
4. QUICK的“下一步确认订单”只有同时满足已确认容量与租期、可售匹配仓位、已选用仓日期才可执行；进入O01继续遵守手机号验证、主动同意协议和整期计价/押金/¥50管理费/订单3小时时效。不删除`core.setTerm()`对容量的守卫、不放宽S5双必选。
5. **BOOKING预约用仓：意向容量、预计租期均为可选**。不确定任意一项也能提交预约；**用仓地址、联系电话仍为必填**。顾问咨询按其独立线索规则，不因BOOKING选填扩展到预约联系信息。
6. 演示状态及数据可以虚构填充，但必须保留用户可理解的自然界面，不添加冗余解释文案，不恢复U01/对比/H01拒绝A/C。

- [ ] 无容量点12月：不会静默确认租期；选择容量后再选12月可继续。
- [ ] 用户主动选容量、选店、选仓、确认租期、日期 → O01，全链无重复需求。
