# H01-ORDER-TIMER-02｜三小时倒计时 + 支付失败释放 + 订单恢复回归

日期：2026-11-11。提交对象：PR #105（叠加 PR #100，Draft/HOLD），未更新 Netlify 或 main。

## 冻结业务规则

| 事件 | 原订单状态 | 库存 | 下次操作 |
|---|---|---|---|
| 创建订单 | pending，支付时限 3 小时 | reserved | 继续支付 |
| 仅关闭支付窗口 | pending，时限不重置 | reserved | 继续原订单 |
| 3 小时内支付成功 | paid_simulated | occupied | 入仓准备 |
| **单次支付失败** | **payment_failed** | **立即释放预留** | **重新选仓并生成新订单** |
| 截止时间到达 | expired | 立即释放预留 | 重新选仓并生成新订单 |
| 价格/库存变化 | invalidated | 释放原预留 | 重新确认方案 |
| 用户取消订单 | cancelled | 立即释放预留 | 重新发起 |

报价仍为 5 分钟；旧订单绝对截止时间不因页面刷新、切换浏览视图或进入付款页而延长。原型 3 小时预留尚未获得正式后端资源政策、支付网关关单时间确认。

## 本次新增修复

- `demo-core.js` 新增 `resumePendingOrder(orderId)`：当用户在等待付款期间修改过容量/租期/城市时，按**原订单 ID**复原仓位与用仓日期；恢复前核验原订单仍为待支付且未超时、仓位仍预留、价格未变化。通过时不重建订单或重置 3 小时；无效时释放原订单预留并拒绝恢复。
- `app.js`：O03「继续支付」按原订单 ID 安全恢复选仓；H01 「继续支付」可**直接进入 O01**，在加载 O01 前恢复并核验该订单；「费用明细」继续进入 O03。
- `br04/bridge.js`：预留/价格变化时保存订单失效与库存释放状态，给出重新选仓提示。付款弹层对 `QUOTE_STALE` 与 `ORDER_EXPIRED` 明确区分。
- `h01-state-policy-01.js`：`payment_failed` 不显示原订单可重新支付的按钮，改为「重新选择仓位」，不改变三小时倒计时逻辑。
- 未变更 S01/S5 推荐规则、视觉母版核心结构、底部四导航、U01 删除及不提供对比的既定规则。
