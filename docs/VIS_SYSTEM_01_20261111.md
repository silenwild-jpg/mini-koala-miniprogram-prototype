## 3. S01 匹配仓位卡：真实代码的两种预览

冻结的**字段**：门店照片、名称、门店标签、地址、距离、仓号、仓位容量、适用说明、整期租金、月租×租期、折扣、立即下单。除既有浏览/匹配/无结果状态外不新增数据。第一二家仍各对应一个匹配仓位，E存第三位，第四位起紧凑。

### A. Balanced｜纵向易读 + 右侧下单

- 首行强化 `3.5m³`，仓号轻标签放到右侧，避免一串紧凑标签与容量抢空间。
- 第二行放完整「适合纸箱、小件家具」，单行可见，不影响价格。
- 第三层左侧 `¥3,120 + 6.5折`、次行 `¥260/月 × 12个月`；右侧独立48px下单。
- 优点：字段关系清楚、下单入口始终右侧、便于连续扫描；预计比基线稍高。
- 风险：为长用途增加一行，第一屏第三位E存可能下移；长金额与按钮仍需要极值校验。

### B. Flow｜价格完整优先 + 整行下单

- 容量、仓号、用途分层保持一致。
- 价格占满有效内容宽度，下面是整行48px「立即下单」。
- 优点：价格极值适配及操作区域最宽，不依赖价格与按钮横排。
- 风险：卡片高很多；第一屏可能只能显示两张门店卡的一部分，不适合高密度长列表。

**现有基线**仍原样保留。新的两个方案只在 S01 预览 iframe 显式 `?vis_system=balanced` 或 `?vis_system=flow` 时生效；默认不应用。源码 `s01-vis-system-01.css` 带独立作用域，不更改 H01/S02/S5布局。

## 4. 不能因为视觉实验改变的产品规则

- 所有人民币金额保持整数截断，同价源；不写「月均」「月均约」，不伪造划线原价。
- 没有完整容量 + 已确认1–60个月租期时，不露出仓号及具体仓位下单内容。
- 匹配态只针对前两家显示各自一个仓位；第三位E存；第四位及以后继续紧凑卡。
- 店名/详情入口和仓位CTA为**不同事件目标**；点击仓位CTA选择正确 `unit_id` 并进入既有交易链路。
- 门店级标签排序跨H01/S01/S02/S5相同，只有数量上限不同。
- 已删除对比功能/U01不可借“高保真设计”恢复。
- 原型可使用演示数据，不要求真实库存、位置或支付验证。
