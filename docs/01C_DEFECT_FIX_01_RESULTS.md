## 2. 修复内容

### X-01｜订单释放时赠期状态转换失败

修改：
1. 只有 `SUBMITTED → APPROVED` 的首次审批必须提供 `approval_id` 与 `approved_by`。
2. `ATTACHED_TO_QUOTE → APPROVED`、`LOCKED_TO_ORDER → APPROVED` 是已有审批权益的回退/释放，不要求重新生成审批元数据。
3. 销售个案原有审批编号和审批人信息随状态转换保留；活动赠期不被错误要求提供销售审批字段。
4. 订单释放前，先预检赠期、优惠券和报价失效所需的状态转换；全部通过后才提交订单状态、库存释放、权益更新、库存版本递增及报价清理。
5. 通用报价失效也改为先预检权益回退，再统一提交，避免失效流程自身出现部分更新。
6. 已审批赠期从 `ATTACHED_TO_QUOTE` / `LOCKED_TO_ORDER` 回退到 `APPROVED` 时，清空实时权益对象上的旧 `quote_id` / `order_id`；销售审批元数据继续保留。

### X-02｜赠期隐藏与费用标签错位

修改：
1. 为 `.fee-row[hidden]` 增加明确的 `display:none`，确保租期不符合赠期门槛时，费用行实际隐藏。
2. 押金标签通过 `#deposit` 所属费用行定位，不再依赖 `.fee-row` 数组固定序号。
3. 赠期行动态插入或隐藏后，不会覆盖押金标签；375/390下均复核赠期恢复显示和押金标签稳定性。
