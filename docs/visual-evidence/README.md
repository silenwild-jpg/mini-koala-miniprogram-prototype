# 视觉证据与签收记录

视觉验收为人工独立门禁。CI 输出的 `visual-guard-report.json` 只能证明机器可判定的结构条件，不可冒充原图签收。

## 一份视觉变更至少需要
- 唯一基础 Commit、中央实际入口、变更后 Commit。
- 最新获批原图文件名及可验证 SHA256；无原件则标记 `NOT_VERIFIED`。
- 375×812 与 390×844 的**相同真实状态**对照图。
- 顶部、中部、底部内部滚动截图；多状态另提供普通浏览、匹配、接近、无匹配、组合、售罄、授权/支付异常等必要证据。
- “原图 → 代码组件 → 浏览器截图 → 归并版本 → 部署 ID”一条可复现引用链。
- 视觉核对：布局层级、留白、照片/容量图、字体字重、价格主次、横幅及 CTA 数量、浮动元素遮挡、旧 CSS 残留。
- 审核人明确签署 `VIS_SIGNED: PASS`；缺项即 `HOLD`。

## S02 审查重点
- 唯一等宽三选项卡：可选仓位 / 服务设施 / 交通路线。默认仓位；三个内容互斥。
- 热门仓型保持用户参考图中的白色紧凑条；**不增加“查看仓位”按钮**；红色框线是圈画标注，不得移入 UI。
- 照片左下存取时间；门店名与地址；需求摘要或轻入口；库存不匹配/组合仓状态；单仓 O01 直接下单。
- 图片素材按最终批准哈希接入；临时 R3 图片不可宣称 R4A 已签收。
- 交通路线地图插槽不得以不真实路线误导成已接入正式地图服务。
