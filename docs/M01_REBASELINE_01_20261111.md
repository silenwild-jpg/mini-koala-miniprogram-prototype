# M01-REBASELINE-01｜「我的」页面历史能力恢复与全站规则接线

日期：2026-11-11。来源：2026-11-03 PRD V1.0、2026-11-10 RC2 V1.1、历史 M01 V1.11/V2.1 与 V2.4.2 生命周期记录。基线：PR #96 HEAD e435bb25eddc8a8ad4c84427ca9883d4ec3e9c16；本分支不是 main，也不代表可访问 UAT 已更新。

## 为什么不能直接复制历史 account.html

RC2 的底部一级「我的」走 app.js 的 renderM01()，而非 parallel/.../demo/account.html。后者是单独的历史租后/账户页面，其组件和导航与中央视图不完全一致。简单覆盖它不能修复主入口。此次只定向改动中央 M01，保留旧子页作为身份验证、入仓准备、联系人管理、咨询及部分记录编辑的过渡承接。

## 修改内容

- 新增 M01 任务区：从统一 order/history 和 core.lifecycleView() 读取待支付、支付失败、已支付待身份验证、待起租、在租、临近到期、续租报价中、退租中、已结束；按业务优先级只突出一个首要任务。其他订单仍可进入订单列表。无订单时按真实保存状态显示找仓需求、预约记录或空态。
- 恢复四个历史直接入口：预约用仓（线索，不冒充已成交或约定到店时间）、我的报价（仅对当前有效快照展示；过期则提示重新核价）、我的订单（中央订单历史）、最近找仓（携同一容量+租期+城市恢复）。
- 增加收藏、优惠券、租后服务（续租/退租/押金/发票）、消息、帮助和个人信息的入口与基础子视图；收藏继续使用现有 S01/S02 视觉收藏会话键，没有复制成独立新 U01。
- 业务状态不重算定价、不创建新订单、不绕开手机号验证：所有正式订单费用与库存由原 SIM_CORE 和 O01 接口负责；M01 只读取和导航。订单历史从中央合同读取，同订单 ID 进入 O03/RN01/EX01/DP01/IV01；身份验证及入仓准备暂使用共享会话数据的旧 account.html 子页。
- M01 页面内部退掉十入口同权网格：账户信息 → 单个当前服务任务 → 四条记录 → 服务权益 → 更多服务。继承品牌绿色，轻分隔线、44/48px控件；专属 CSS 仅适用 .page-M01，不更改 H01/S01/S02/S5 或全局母版。
- 不新增对比组件，不显示「参考价」技术文案，不向真实用户承诺本地线索已通知顾问或实际付款已收款。

## 已知局限与保留门禁

- 主入口模块复用现有会话；并不拥有跨设备云端同步能力。
- 历史旧 account.html 的服务详情仍需要后续迁回中央视觉系统；不能将其当作两套独立主 M01。深链切换需专项检验返回路径和底栏。
- 报价对象仅现有活动 quote；没有完整多报价历史实体。无数据时不编造已保存报价条目。
- 预约记录只读中央个人线索；还未实现 CRM/销售受理状态同步，不将 saved_locally 当作已确认约定时间。
- 续租/退租到期/押金/发票使用原生命周期，财务或经营未确认事项继续 HOLD。
- PR #98/#99/#100 尚在各自独立分支。最终集成须对比唯一来源与修改范围，严禁整包归并。本 PR 不更新已批准 H01/S01/S5 原型，也不自动并入 main。
