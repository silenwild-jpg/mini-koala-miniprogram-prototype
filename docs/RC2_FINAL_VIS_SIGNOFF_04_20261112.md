## 本轮产品契约（原型阶段，不接真实外部服务）

### RN01 报价→付款→生效
1. 续租需求 `QUOTE_PENDING` → 评审核报价 `QUOTE_READY`；方案确认后是 `PAYMENT_PENDING`，而不是已完成。
2. 普通用户可点“立即付款”完成原型支付体验，也可以“稍后支付”；对应 `COMPLETED` 或 `PAYMENT_CANCELLED`。显式评审页 `review=1` 可触发 `PAYMENT_FAILED`，普通用户不能主动选择付款失败。
3. `PAYMENT_CANCELLED`、`PAYMENT_FAILED` 允许“继续付款”，恢复**原订单和原报价 ID**，不重复建立续租需求。异议价格仍需业务侧按报价规则裁定。
4. **只有 `lifecyclePayRenewal(...,'success')` 才延长总租期、写入续租付款 ID 和可开票记录**。首次订单3小时保留/失败/取消规则完全独立。续租金额继续采用评审报价的整元月租×续租月数；累计租期仍不超过60个月。
5. 续租支付完成后，自动清空旧租期输入草稿。原有基于完成状态生成的发票付款清单无需改变，状态会自然区分。
6. 这是产品体验原型：不发生真实资金扣款，不在用户界面添加“模拟/演示”等冗余描述。未来接入真实支付时，成功必须由支付结果回调产生，不能继续采用前端直接置成功的实现。

### M01 用户身份提交→待核验→审核结果
1. 普通 `account.html?view=identity&id=...` 页：待验证/失败可进入姓名与证件号码表单，填写后只转为 `reviewing`，即“核验中”；不允许普通用户选择“验证通过/未通过”。
2. 此原型**仅做非持久化字段格式校验**，不会将姓名、身份证号码写入演示 state、sessionStorage 或发起第三方身份认证请求；正式产品必须另行建设有授权与隐私保护的认证路径。
3. 只有显式 `debug=1` 的内部审核视图、且订单已经申请核验，才展示“审核通过/审核未通过”。用户界面保留失败重试和正在核验状态，不出现内部测试措辞。
4. 核验中的订单没有入仓权限；提前起租、已退租、租期到期等原有门禁规则完全保留。测试覆盖两笔不同订单隔离及待起租状态。
