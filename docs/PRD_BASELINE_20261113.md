# 迷你考拉仓 PRD 基线｜2026-11-13
## 定位
当前为产品原型策划、功能演示和视觉探索阶段。当前验收对象为Web原型，不是已交付的微信原生小程序。演示数据允许合理虚构以覆盖用户访问场景，但不得描述为真实库存、真实定位或真实交易核验。

## 页面范围
H01首页；CAP容量选择；ITEMS按物品估算；S01附近门店；S02门店详情；S5推荐仓位；BOOKING预约用仓；QUICK快捷下单；O01确认订单；M01我的/资产与订单生命周期。U01独立仓位详情页已删除，不属于当前有效主链路。

## 路径
首页/门店浏览：H01→S01→S02→O01（符合下单条件时）。
容量估算：CAP/ITEMS→S5→O01。
快捷下单：QUICK→O01。
预约用仓：BOOKING创建销售线索，不等于创建订单。
M01承接资产、订单、续租、支付及租后服务生命周期。

## 已知原则
- 容量和租期均为推荐前必选；S5继承两者，修改后需更新推荐。
- S5默认两个门店、每店一个最匹配仓位，并保留考拉E存运营位；精确排序和兜底以最新推荐策略文件为准。
- 整期租金为主视觉，月租为次级；押金按一月租金，管理费每单¥50；组合仓押金汇总、管理费整单一次。
- 手机号验证为正式报价/下单门禁；手填联系电话不能替代验证。
- 示例价格、库存、公里数和促销允许演示填充；演示测试不等于生产验证。

## 视觉
375×812基础视口，390×844并行回归；左右边距参考16px，主按钮高度48px。不得增加冗余解释文本、无必要容器/边框/阴影/装饰。
S01/S5统一照片尺度、信息层级和标签语义，不要求DOM同构。S02保留“可选仓位/服务设施/交通路线”三Tab。S5前两张推荐门店卡使用小尺寸门店照片。
