## 3. 当前明确的演示缺口

### DEMO-01｜㎡输入的换算口径需产品确认（不作为当前代码缺陷直接修改）
证据：CAP目前以2.5m作为面积换算高度；具体仓位fixture中，小仓存在2.0m高度，3m³及以上标准仓样本以2.5m为主。㎡输入发生在具体仓位选择之前，因此无法仅凭用户输入唯一反推出实际仓高。
当前前端策略：保留现有2.5m演示换算，不擅自改成按容量档位推算，避免1.2㎡等输入因仓高假设变化而改变容量、推荐仓位及价格。实际仓位尺寸仍在S02展示。
待产品/业务确认：㎡输入表示地面占地面积、按统一标准层高折算的估算体积，还是按不同仓型分别计算。确认前不改变核心换算公式。

### DEMO-02｜促销场景不够完整
证据：br03-demo-snapshots.js目前有两个仓位级特价campaign；demo-core.js有优惠券领取、使用与服务权益处理；尚未看到同一套可切换演示数据覆盖所有促销展示态。
当前前端任务：补充可切换的演示活动场景，至少覆盖：
- 普通仓无活动；
- 仓位特价活动；
- 长租折扣；
- 送一次基础搬运（符合/不符合资格）；
- 固定活动赠送租期；
- 销售个案赠送租期；
- 优惠券可用/不适用/锁定/已使用；
- 多权益组合展示（作为UI演示状态，不等同生产叠加规则已批准）。
确保H01/S01/S02/S5/O01/M01各自展示与上下文一致；不因未确定真实资格而隐藏活动模块。
后端待确认：活动配置后台、资格、叠加顺序、授权、合同/退款/续租影响。
