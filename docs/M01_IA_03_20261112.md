# M01-IA-03｜「我的」信息架构与多仓位资产视图

M01 继承 PR #108 的前两轮恢复成果。当前仍属于原型策划、内部演示和可视化评审阶段，不验证真实门店、促销、库存、退款或开锁数据。H01 A+C 视觉探索未导入。

## 页面分工与结构（本轮已实施）

- H01：当前最高优先级任务 + 找仓。
- M01：我的全部有效用仓资产、订单/预约/报价/最近需求，以及服务与权益。
- O03：同一订单的履约细节与可办理动作。
- RN01/EX01/DP01/IV01：按订单 ID 分流。

M01 结构：

1. 简洁账户头部，个人信息只保留一次入口。
2. 当业务队列有待办时展示单条当前任务（待支付、身份验证、临期、续租进度、退租与押金等），继续消费共享的 H01_STATE_POLICY 派生结果。纯普通在租、无紧急任务时不重复显示“我的仓位”任务卡。
3. 有效租约下展示「我的仓位」平面列表，按订单为单位，每行包含门店、仓号与容量、阶段状态、已确认租期/起止信息。组合仓不拆成多个合同。首页最多展示两笔有效租约，“查看全部 N 处”可进入全部列表；点击仓位进入该订单的 O03，不新造订单源。
4. 「我的记录」：我的订单、预约与需求、报价方案、最近找仓。
5. 「服务与权益」：收藏、优惠券、有效付款订单才显示租后服务入口、消息。
6. 「更多服务」：客服帮助；避免重复的个人信息入口。

## 状态与数据边界

- 「我的仓位」只包括状态 active、upcoming、returning、expired 的已付款租约；ended 及押金完成后归历史订单，退款中则在当前任务/租后服务查询。普通在租不出现两次相同按钮。
- 多笔租约时最多两笔仓位预览，全部列表展示所有有效租约，不以 H01 只选一条主任务为限。
- 组合仓保留一个订单 ID，分别显示多个仓号+对应容量，点击仍打开原订单 O03。
- 个人预约 SIMULATED_BOOKING_LEAD、顾问咨询 ADVISOR_CONSULTATION、企业需求 ENTERPRISE_REQUIREMENT 均在“预约与需求”中展示；已保存不代表商家已受理，撤回仍作为历史记录。
- “报价方案”读取当前共享 quote，显示有效/到期状态，不伪装成完整历史报价。报价时效维持五分钟，失效需要重新核价。
- “最近找仓”读取目前唯一的需求快照：无订单/当前未下单选仓/有效报价时可继续；已有订单且无独立新选择时标记“最近参考”，只提供新找仓而非自动恢复旧订单。**无法识别再次选择相同容量/租期、但尚未选仓的新意图**，需要后续引入明确的需求版本/意图 ID；本轮没有自行扩写中央核心。
- 删除旧 account needs 子页的裸内部 lead ID 和“仅本地保存”提示，不对外宣称 CRM 收单成功。
- 价格、管理费、优惠券、手机号验证及 H01 三小时原订单恢复均不修改。无对比、无 U01。

## 视觉约束

- 375×812 和 390×844；列表用 1px 轻分隔线，无新增大卡、阴影或配图。
- 仓号与容量合为同一信息组；整体一行对应一个订单，组合仓以多个仓号+容量并列或自然折行。
- 操作可触达范围至少 44px；当前任务主按钮不小于 48px。
- H01 原营销母版、S01/S02/S5/O01 视觉与业务源码不改，原 CSS 使用 .page-M01 限定作用域。
