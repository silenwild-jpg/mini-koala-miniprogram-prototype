# H01-M01-FLOW-QA-01｜跨页订单 ID、导航恢复及租后链路门禁

日期：2026-11-12。业务基线 PR #126（M01-IA-03 HEAD 8a4e7127954fc48f209b712d7656a9fb567b0340），其父级为 H01-M01-CONTRACT-01 PR #125，底层 H01 单一候选 PR #116。本任务仍在独立嵌套分支，不涉及 H01 A+C 未签收探索（PR #123）。

## 已发现的可复现源码风险（P1）

之前中央路由的 go(O03/RN01/EX01/DP01/IV01) 只把 page 放进 URL，不写入订单 ID；popstate 从 URL 只恢复 page/store，selectedOrderId 仍是内存里最近一次选中的 ID。

当用户先看订单 A 的租后服务，再从 M01 看订单 B，浏览器返回 A 的历史路由时，可能显示 B 的详情——这是确实存在的源码状态依赖，不是已执行浏览器复现。

### 修复

新增 m01-order-route-01.js，使用唯一的订单 URL 契约：
- O03、RN01、EX01、DP01、IV01 的每次正常导航均在 URL 显式携带 order=<订单 ID>。
- 首次打开以及 popstate 优先使用 URL 中的 order，若无 order 则兼容旧会话的最近订单 ID；显式提供的错误或空 ID 不自动切换为其他有效订单。
- 已选择的有效订单 ID 同步至会话，保证从订单详情进入四种租后服务时一致。
- 不把订单 ID 附加到 M01/S01/S5 等非订单页面，避免无关状态泄漏。
- 未修改任何中央订单计价、订金、续租、退租、开锁业务实现。

## 状态矩阵

- 未下单：H01 找仓；M01 无有效仓位。
- 待支付：H01/M01 同一优先级、3 小时绝对截止时间，原订单恢复。
- 支付失败/超时：原单禁止继续付，重新选仓新订单意图。
- 已付未验证：跳转对应订单的身份验证；入仓权限关闭。
- 待起租：可以看入仓指引，不允许提前开锁。
- 在租/即将到期：多个有效订单均可从 M01 找到，RN01 累计租期不得超过 60 月。
- 退租/验仓：EX01 不会错误关联其他活跃订单；不能由客户直接标记验仓成功。
- 押金待退/已退：DP01 绑定退租订单。验仓通过的租约不计入有效仓位，仍可查历史订单。
- 发票：IV01 针对当前订单的已付款记录，不与另一笔订单混用。
