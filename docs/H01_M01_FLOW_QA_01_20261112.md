# H01-M01-FLOW-QA-01｜跨页订单 ID、导航恢复及租后链路门禁

日期：2026-11-12。业务基线 PR #126（M01-IA-03 HEAD 8a4e7127954fc48f209b712d7656a9fb567b0340），其父级为 H01-M01-CONTRACT-01 PR #125，底层 H01 单一候选 PR #116。本任务仍在独立嵌套分支，不涉及 H01 A+C 未签收探索（PR #123）。

## 已发现的可复现源码风险（P1）

之前中央路由的 go(O03/RN01/EX01/DP01/IV01) 只把 page 放进 URL，不写入订单 ID；popstate 从 URL 只恢复 page/store，selectedOrderId 仍是内存里最近一次选中的 ID。

当用户先看订单 A 的租后服务，再从 M01 看订单 B，浏览器返回 A 的历史路由时，可能显示 B 的详情——这是确实存在的源码状态依赖，不是已执行浏览器复现。

### 修复

新增 m01-order-route-01.js，使用唯一的订单 URL 契约：
- O03、RN01、EX01、DP01、IV01 的每次正常导航均在 URL 显式携带 order=<订单 ID>。
- 首次打开以及 popstate 优先使用 URL 中的 order，若无 order 则兼容旧会话的最近订单 ID；显式提供的错误或空 ID 不自动切换为其他有效订单。
- 已选择的有效订单 ID 同步至会话，保证从订单详情进入四种租后服务时一致。
- 不把订单 ID 附加到 M01/S01/S5 等非订单页面，避免无关状态泄漏。
- 中央引擎只定向修正 UTC+8 业务日期与租约状态、入仓资格的两处不一致；计价、订金、三小时支付、续租/退租流程和真实开锁均不变。

## 状态矩阵

- 未下单：H01 找仓；M01 无有效仓位。
- 待支付：H01/M01 同一优先级、3 小时绝对截止时间，原订单恢复。
- 支付失败/超时：原单禁止继续付，重新选仓新订单意图。
- 已付未验证：跳转对应订单的身份验证；入仓权限关闭。
- 待起租：可以看入仓指引，不允许提前开锁。
- 在租/即将到期：多个有效订单均可从 M01 找到，RN01 累计租期不得超过 60 月。
- 退租/验仓：EX01 不会错误关联其他活跃订单；不能由客户直接标记验仓成功。
- 押金待退/已退：DP01 绑定退租订单。验仓通过的租约不计入有效仓位，仍可查历史订单。
- 发票：IV01 针对当前订单的已付款记录，不与另一笔订单混用。

## 2026-11-12 新增可执行发现 P1｜UTC+8 起租与日界线

- 已确认旧中央引擎将今天/日期输入用 UTC+8 计算；但是 lifecycleView() 的 dayNow() 和 enterStorage() 提前起租阻断使用 UTC 日期。北京时间 2026-11-12 06:14（UTC 11 月 11 日 22:14）创建并付清当天起租的订单，旧版被错误标为 upcoming、入仓入口抛出 BEFORE_START。
- 修复：复用既有 today()（UTC+8）作为唯一租赁日历基准，使生命周期状态、访问资格、门禁演示入口一致。未来起租日期仍不可提前访问，已到期订单仍禁止入仓。
- H01 及 M01 原有剩余天数分别使用瞬时时差和客户端本地日期，可能在 UTC+8 清晨多算一天。统一使用北京时间的日历日期差；临期未到期显示正确天数，到期当天切换至到期状态。
- 使用固定时钟再现与反证：2026-11-11T22:14:00Z → 北京时间 2026-11-12 06:14。旧 H01=upcoming/BEFORE_START；本候选 H01=active/通过入仓资格。到期 2026-12-12 的订单在北京时间 2026-12-11 06:14 显示剩余 1 天；在 12 月 12 日 00:01 转 expired。
- 新增 scripts/verify_h01_m01_business_date_01.cjs，独立固定时钟回归已通过；加入本候选的 CI 源码和业务规则门禁。此项涉及中央核心的两处日期判定，因此必须在统一候选归并前显式检查影响，不得将其默认为纯 M01 CSS 修复。


## 375/390 运行截图复审补充｜订单页面滚动位置隔离（P1）

- 首次成功的同 SHA 浏览器运行 #43113639340 已通过三套 375/390 浏览器测试，并提供 63 项证据文件（包括结果 JSON、流程/信息架构/合同截图）。人工浏览后发现：多订单返回 A 详情的截图位于详情下半部。
- 注意：单纯返回到此前阅读位置可以是正确交互，单张截图并不能证明故障。因此复核源码而不是将该截图直接认定为 Bug：原 positions[page] 只按 O03/RN01 等页面名保存滚动位置，A/B 两个订单确实共享同一个 key；popstate 更换订单 ID 时存在读写错位风险。
- 定向修复为 positions[page + '|' + orderId]；新增 displayedOrderId 保护，避免 popstate 在同一 O03 页面切换不同 ID 时将旧 DOM 滚动位置写入新订单的 key。
- 新增浏览器复测：先明确保存 O03 A 在顶部，再将 O03 B 滚动至底部，通过浏览器历史返回 A，要求恢复 A 自己的位置，禁止继承 B。对应 375/390 截图自动复产。
- 该补充不改变页面信息架构、按钮、样式、H01 首页视觉或门店卡布局。只有重新运行最终 SHA 的浏览器测试通过后，才能关闭此 P1。
