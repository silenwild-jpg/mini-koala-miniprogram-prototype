# PROTO-RULE-RESTORE-07｜内部真实用户试用准入卡

**目标：** 先验证新用户是否能够高效理解“找附近门店→选仓→验证→订单”与“容量/物品估算→S5推荐→选仓”两条主链，不以此替代设计批准或微信真机验收。

## 试用分级和准入

1. **本机受控业务探索：CONDITIONAL GO。** 仅使用固定RESTORE-06隔离ZIP与模拟场景，明确告知距离、价格、门店、手机号、支付、库存均为演示；不录入真实个人信息，不擅自公开访问地址。
2. **多设备私有内部真实用户试用：HOLD直至**受测手机可访问的内部门禁站点可用（SSO/白名单）、数据与SHA固定、主持人告知模拟性质、任务卡/异常记录准备完毕。
3. **最终高保真设计验收：HOLD。** 须收到最新三筛选S01批准整页图，且H01/S01与当前双尺寸运行图按相同数据同状态逐区签字。不能依靠CI截图推定原图被批准。
4. **微信真机/生产交易：不在范围内。** 本PR不发布、不合并main。

## 建议6项试用任务

| ID | 真实口语任务 | 完成标准 |
|---|---|---|
| T01 | 找一家附近门店，看看存几箱物品的选项 | H01→唯一S01、能理解位置与租金 |
| T02 | 按停车或近地铁服务筛选，进一家门店再返回 | 三筛选操作明确、S02返回无丢失 |
| T03 | 预计3m³存6个月，尝试通过估算找到方案 | CAP/ITEMS→S5保留容量和租期 |
| T04 | 不喜欢推荐仓位，去查看更多门店并选择仓位 | S5→S01→S02/O01且不进入U01 |
| T05 | 先拒绝手机号授权，后来再决定下单 | 可浏览基础信息；正式报价/订单受门禁 |
| T06 | 模拟支付失败、恢复；续租输入61个月 | 失败后回S01，续租错误不自动提交 |

**建议样本：** 6–8名内部参与者，其中至少4名不参与当前设计/开发。所有观察记录使用匿名P1、P2等编号；屏幕录制先征得同意。

### 每位任务结果记录

`受试者编号 / 设备与屏幕宽度 / 场景及SHA / 任务号 / 完成-协助-失败-未测 / 用时 / 卡点 / 实际原话 / 是否被提示 / 缺陷ID / 证据 / 主持人`

- **P0阻断**：报价、库存、订单串单；手机号绕过；关键操作卡死；错误支付结果；数据泄露。
- **P1重要**：主要入口不可理解、筛选反馈混淆、用仓需求丢失、模拟距离被误解为真实距离、底部按钮遮挡。
- **P2建议**：微文案、间距、非阻断的动效与装饰，任何修改仍受VIS-GUARD约束。

**推荐探索阶段验收门槛（待实际测量，不是结果）：** T01–T04无主持人提示完成率≥80%；P0=0；所有P1有负责人和修复/复测方案。试用结束后方可形成真实用户意见；当前无已执行的真实受测数据。
