## 1. 推荐位规则核验

### H01 首页第三位：灵活运营位
代码：demo/home-recommend-policy.js。
- 前两位先按可信距离排序；若距离不可验证，保留演示目录顺序。
- 第三位从剩余门店优先选operatingTag为“特价仓”的门店，其次任一运营标签，再次第一剩余门店。
- 这与用户近期明确的“H01第三位是灵活运营位，与S01第三位固定E存不是同一规则”方向一致。
- 风险：当前fixtures.js给门店按索引轮转operatingTag，运营位规则虽独立，但促销资格来源不可靠；见CODE-04。

### S01 附近门店第三位：固定考拉E存
代码：demo/s01-r2-bind.js。
- store序列i===2时插入estoreCard。
- 无匹配空态也插入E存卡；门店不足2家时仍补E存卡。
- 第4位及以后使用compactStore整卡直达详情，不恢复展开仓位卡。
- 结论：固定E存位置与近期规则相符，未发现首页灵活运营位规则污染S01。

### S5 考拉E存
代码：demo/br04/s5/index.html + br04/bridge.js。
- 页面有独立.estore区块，位于推荐门店卡之后。
- renderS5将B.s5Offers结果截取前2家；E存作为独立服务入口，不混入前两家实体门店排序。
- 结论：当前代码结构符合“两家实体门店推荐 + 独立考拉E存服务位”的信息架构方向。
