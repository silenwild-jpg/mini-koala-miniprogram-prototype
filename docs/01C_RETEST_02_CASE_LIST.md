## 2. 统一执行约束

1. 每次运行使用独立 BrowserContext，不继承上一次 sessionStorage。
2. 每次运行绑定一个逻辑用例、一个赠期来源和一个视口。
3. 每次运行记录截图、Playwright Trace、状态快照、控制台异常和 pageerror。
4. 页面入口、表单、按钮、租期修改、支付结果等用户行为通过浏览器真实点击。
5. 仅允许通过基线内官方演示场景建立前置状态；测试驱动的订单终止操作必须明确标记为受控诊断，不得伪装成普通用户操作。
6. 不使用审核按钮或 debug 深链作为普通用户路径通过依据。
7. 不修改业务源码、业务规则、演示价格、库存数据、正式路由或 main。
8. PASS / FAIL / BLOCKED 独立判定；NOT IN SCOPE 作为子项范围登记，不计入 PASS。
9. 页面错误不得仅因出现 toast 而判定为成功。
10. 本轮只报告当前基线事实，不修复缺陷、不合并、不部署。

## 3. H 组

### H-T26｜租期变更与赠期资格

用例：H-T26-CAM、H-T26-SALES。

前置条件：
- 指定赠期已批准。
- min_months=6。
- 赠期1个月。
- 已选仓位 SIM_BJ01_U04，租期6个月。

步骤：
1. 进入 S02，真实点击目标仓位的「立即下单」。
2. 进入 O01，确认赠期行。
3. 真实点击租期，改为3个月。
4. 记录赠期行 hidden、计算样式 display、visibility、文案及标签。
5. 恢复6个月。
6. 再次记录赠期行。
7. 勾选协议，真实点击确认订单，检查赠期只锁定一次。

预期：
- 3个月低于门槛，赠期行必须隐藏，计算样式为 display:none。
- 不得残留“赠送1个月”可见文案。
- 赠期行标签必须是“赠送租期”，不得被押金标签覆盖。
- 恢复6个月后赠期行重新显示。
- 建单后赠期为 LOCKED_TO_ORDER，订单快照仅有一条赠期。

缺陷关联：X-02（P1）。

### H-T27｜终止旧订单后重新报价

用例：H-T27-CAM、H-T27-SALES。

步骤：
1. 真实页面点击选择仓位并创建第一笔待支付订单。
2. 记录 quote_id、order_id、库存和赠期状态。
3. 使用受控诊断调用现有 cancelOrder 接口，捕获异常；该步骤只用于验证终止状态机，不作为普通用户取消入口。
4. 检查订单、报价、库存、赠期是否完整释放。
5. 真实页面重新选择仓位并创建第二笔订单。
6. 检查新报价 ID 与赠期关联。

预期：
- 旧订单终止。
- 原报价失效。
- 赠期恢复 APPROVED，旧 order_id 清理。
- 新报价使用新 ID。
- 赠期只关联第二笔订单一次。

缺陷关联：X-01（P1）。

### H-T28｜普通用户取消待支付订单

用例：H-T28-CAM、H-T28-SALES。

步骤：
1. 真实页面创建带赠期的待支付订单。
2. 进入正式 O03 订单详情。
3. 检查普通用户是否存在取消入口。
4. 使用受控诊断调用 cancelOrder，检查底层状态机；不得将该调用计作普通用户路径。
5. 重新从页面选择仓位并下单，检查赠期是否重挂。

预期：
- O03 应提供普通用户可见的取消待支付订单入口。
- 取消后订单变为 cancelled。
- 仓位释放、报价失效、赠期恢复 APPROVED。
- 新订单只重挂一次。

缺陷关联：X-01（P1）、X-03（P2）。

### H-T29｜待支付订单自动过期

用例：H-T29-CAM、H-T29-SALES。

步骤：
1. 真实页面创建待支付订单。
2. 记录初始状态。
3. 使用 Playwright 可控业务时钟推进超过3小时。
4. 等待页面原生1秒巡检机制执行。
5. 检查订单、仓位、报价和赠期状态。
6. 真实页面重新选仓并下单。

预期：
- 订单自动变为 expired。
- 仓位释放。
- 报价失效。
- 赠期恢复 APPROVED，旧关联清理。
- 新报价和订单可以重新挂入赠期。
- 记录页面异常和完整 Trace。

禁止直接写入订单 expired 状态。

缺陷关联：X-01（P1）。

### H-T30｜支付失败后重新下单并成功支付

用例：H-T30-CAM、H-T30-SALES。

步骤：
1. 真实页面创建带赠期的待支付订单。
2. 在支付流程弹层真实点击「体验支付失败流程」。
3. 检查订单、库存、报价和赠期。
4. 真实页面重新选择仓位并创建新订单。
5. 真实点击「体验支付成功流程」。
6. 检查赠期最终状态和发放次数。

预期：
- 第一笔订单为 payment_failed。
- 仓位释放、报价失效、赠期恢复 APPROVED。
- 第二笔订单重新挂入赠期。
- 成功支付后赠期变为 GRANTED，发放次数严格为1。
- 不残留旧 LOCKED 关联。

缺陷关联：X-01（P1）。

## 4. G1 组

### G1-01｜我的收藏

步骤：
1. 从 M01「我的」真实点击「我的收藏」。
2. 检查门店与仓位收藏。
3. 访问旧链接 account.html?view=favorites。

### G1-02｜优惠与权益

预期：新版统一视图包含券、权益、赠期；旧视图仅列券。X-05 作为口径差异登记，不作为数据丢失。

### G1-03｜运输需求

G1-03A 遗留能力：
1. 无已付款订单时进入 account.html?view=transport，检查空状态。
2. 使用官方演示数据创建一笔已付款订单。
3. 重新进入旧链接，选择关联订单。
4. 填写运输地址和日期，真实点击保存。
5. 检查 services[id].transport 写入及 awaiting_advisor 状态。

预期：运输需求依附已付款订单，保存到关联订单服务记录。

G1-03B 正式路由：
- 当前运输需求属于 account 子视图，不是独立正式路由。
- TRANSPORT 不计入16项正式路由 PASS。
- 该项标记 NOT IN SCOPE，不新增独立路由。

### G1-04｜中央壳旧手机号层
