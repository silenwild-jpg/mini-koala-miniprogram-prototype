依据：当前f2fccf源码的品牌与通用样式；本轮已读取的微信官方设计指南。A/B探索已停止，不作为本文件的批准依据。

## 1. 视觉目标与适用范围

保持品牌识别，让容量、价格、状态和下一步操作容易理解。适用于国内微信小程序的个人与企业服务页面；本文件先统一基础视觉，不规定新的页面布局或业务流程。真实交易、库存、登录和顾问规则不由视觉规范决定。

本文件区分四类：**用户已确定**为页面纯白底；**现有值**来自源码；**建议值**用于归一和补缺；**平台要求**以官方正文为准。用户确定白底不等于同时批准其他色值。

### 2.2 配色使用规则

- 页面、内容区、导航和底部操作区默认使用纯白。用留白、标题和轻分隔线建立层级；不再用浅灰绿铺整页，也不将每个分区染成浅色卡片。
- 品牌绿用于主要按钮、链接和选中；浅绿只在选中项或短提示中局部使用。大块深绿仅用于确有需要的品牌图片或宣传区域。
- 中性灰负责辅助信息；深橙只突出本屏最重要的价格，其他金额可用主要文字色。警告、错误、蓝色信息提示按实际状态出现，不作为日常装饰。
- 一个任务屏突出一个主要操作；次要操作采用白底描边或文字。首页的并列服务入口可同等呈现。
- 价格采用深橙色，颜色之外必须显示“整期租金”“月租”“合计”等口径。不可把所有折扣、标签和提示都染成价格色。
- 成功、警告、错误必须同时带明确文字或图标。选中态同时使用描边/标识，不能只靠色差。
- 轻分隔线只做分组；输入边界、焦点与选中需要使用更明确的控件边框或品牌色。
- 文字落在照片上时按实际图片加遮罩并检查对比；不能仅靠文字阴影保证可读。
- 暂只制定浅色方案；深色模式作为后续适配任务，不自动反转颜色。

### 2.3 已知颜色差异及归一建议

当前首页出现 `#006C54` 等偏深青绿色；通用页面定义 `#2F6B4F`。两者均是实现事实，不能说源码已经全站统一。建议以首页品牌识别的主色归一常用控件。用户现已确定页面纯白底，原源码背景#F8FAF9仅作为历史实现事实，不再是本版页面底色建议。其余色值仍待审阅，不直接覆盖源码。

通用样式定义价格橙 `#D56A1C`，其对白底对比为 3.55:1。建议关键价格文字加深为本稿价格色；原橙色可在满足对比的较大展示或非文字装饰中另评，不作为小字默认值。

本稿将普通文字≥4.5:1、必要控件边界≥3:1作为设计验收目标；这是本项目采用的可读性目标，不将其表述为微信统一规定的像素/色值。

## 3. 字体与字号

使用系统中文字体，避免首阶段加载额外字体；数字使用等宽数字特性便于金额对齐。常规正文400、操作与小标题600、重要标题700，少用所有文字加粗。

|层级|字号/行高|字重|用途|
|---|---|---|---|
|品牌展示|28 / 38|700|首页少量主标题|
|页面标题|24 / 34|700|页面核心标题|
|分区标题|20 / 28|600|内容分组|
|导航标题|17 / 24|600|顶部导航|
|正文与字段|16 / 24|400–600|正文、输入、字段标签、按钮|
|辅助说明|14 / 22|400|单位、帮助与补充|
|非关键信息|12 / 18|400|图片说明等次要内容|
|核心金额|28 / 36|700|整期或合计主金额，单位另列|

以上为视觉/Web逻辑像素基准，不能把它们直接当成微信指南中的pt。关键费用条件、错误与状态不压成12px小字。长标题自然换行，避免靠删减事实或缩小字号塞入一行；放大字体后检查截断与按钮高度。

## 4. 间距与布局基础

采用4、8、12、16、24、32六档。页面左右默认16；同组元素8或12；字段之间16；分区之间24，必要时32。单位、金额和说明靠近，相关信息不散落。

以375和390两种宽度检查；内容宽度随设备变化。文字输入、弹层和底部操作需检查键盘与安全区。页面视觉规范不固定状态栏或官方菜单的假尺寸；原生实现应使用官方能力和实际设备验证。

## 5. 圆角、边框与层级

小标签8，按钮/输入12，图片/内容分组14，底部弹层上角20。胶囊形仅用于确有胶囊语义的小标签或分段控件，不让所有元素都变成胶囊。

边框默认1逻辑像素。内容分组优先用留白、底色或轻分隔；避免多层套卡片。常规内容不设阴影；确需浮起的面板可用 `0 4px 16px rgba(31,41,35,0.08)`，遮罩可用 `rgba(16,36,26,0.45)`。这些为建议效果值，需随实际层级验证。

## 6. 常用组件视觉规则

|组件|规则|关键状态|
|---|---|---|
|主按钮|品牌底/白字，48高，12圆角，16字号|默认、按下、禁用、进行中|
|次按钮|白底/品牌字，清楚描边，与同排按钮等高|默认、按下、禁用|
|文字操作|品牌色，名称具体；小图标扩展触达区域|默认、按下、焦点|
|输入框|白底、控件边框、48最小高；标签常驻，提示不代替标签|输入、禁用、错误、聚焦|
|单/多选|选中显示品牌描边、浅绿底和明确标识|未选、已选、不可选及原因|
|标签|表示事实或状态，14字号优先，颜色与语义一致|可用、待确认、异常|
|价格区域|整期主金额突出；月租、押金、管理费、合计层级分明|正常、待核价、已变化|
|弹层|标题、内容、取消/确认清楚；短任务用层，长表单用页面|打开、输入、错误、关闭|
|导航|当前项可辨，图文风格一致；避让官方菜单|当前、非当前、返回|

Web触达目标默认44×44；可见图标建议24，触达区域不随图标一起缩小。它们是本稿默认值，不声称微信要求所有控件恰为44px。原生组件能满足需求时优先使用，再评估TDesign MiniProgram；本文件不等于已安装或选定组件库。

## 7. 图片与图标

沿用已有品牌标识和真实素材。场景图统一光线、裁切与比例，明确图片区和文字区；不把带大段烘焙文字的截图当成通用缩略图。不拉伸照片，不把环境示意当作具体门店实拍证明。

同一套图标保持线宽、圆角与填充方式一致；沿用现有导航资产，必要时统一替换整组。不要混用emoji、线性图标与随机实心图标。重要图标操作保留可读名称。

## 8. 状态、反馈与动效

操作后就近反馈；异步按钮显示进行中并防重复。错误持续可见，说明如何恢复；不只闪过Toast。空态说明下一步；不可选的仓位写明状态。动效仅解释状态变化，建议150–250ms；减少动态效果设置下简化，未有必要不做整页入场动画。

返回保留已确认内容；弹层取消不写入；关闭后焦点回到触发项。提交结果与真实状态一致，“本地保存”不能写成“顾问已受理”或“预约成功”。本节约束信息表达，不改变现有业务契约。

## 9. 微信平台衔接

已读取的官方指南支持重点突出、流程明确、导航可退、减少输入、及时反馈和跨页一致；官方菜单内容不可由业务自定义，需预留区域。app配置对tabBar列表给出2–5项约束，设计指南另建议不超过4项；必须区分配置约束和设计建议。

本文件的品牌绿、字号表、圆角及44px触达默认是项目建议，不是微信官方色板强制值。Web的px、微信指南的pt和原生rpx不能混为一种单位；如采用750rpx布局基准，32rpx仅在375宽时相当于16逻辑像素，在390宽会变化，不能将全部值机械乘2。

官方菜单实际位置、安全区、软键盘、字体放大、渲染器及iOS/Android差异留原生验证。来源：[微信设计指南](https://developers.weixin.qq.com/miniprogram/design/)（本轮访问显示2026-04-20编辑）；[app配置](https://developers.weixin.qq.com/miniprogram/dev/reference/configuration/app.html)（本轮访问显示2026-11-10编辑）；[TDesign MiniProgram](https://tdesign.tencent.com/miniprogram/overview)。核验日期2026-11-15；未声称已通过微信原生或发布验收。
