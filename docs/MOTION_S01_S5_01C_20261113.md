## 源码修复范围
1. `demo/index.html`：在 `app.js` 前加载 PR #163 的同源 `br04/s5/location-ranker.js`，使中央 S01 可以计算 S5 已选坐标。

3. 计算 S01 门店的 **从选点到物业坐标的直线约距**，并统一应用于：
   - 推荐排序（最近第一；周边更低价优先作为第二），
   - 距离排序及 1/3/5/10km 筛选，
   - 门店卡片上的公里数。
4. 地图坐标缺失时，该门店不能沿用此前城市默认公里数冒充“距已选点的距离”；不影响其他门店的展示。
5. 继续沿用 S01 原本三个筛选、第三位 E 存、第四位起紧凑卡及既定直接下单入口；不改变 S01 的 HTML / 卡片 CSS，也不新增标签、解释性说明或考拉图案。

## 实现取舍
- 继续使用现有 `stage.replaceChildren(...nodes)`，不在本轮引入新的列表动画框架、路由重构或缓存层，以免改变已批准的门店卡视觉及焦点机制。S01 搜索框处于该节点树之外，刷新时应保留输入焦点，需浏览器验证。
- 不增加动画到价格文本、整期租金、押金、优惠、下单按钮或订单状态。
- 本次只修复 **S5 → S01 的位置源一致性**；首页与 S02 地图位置的跨页共享不包含在本次范围。
