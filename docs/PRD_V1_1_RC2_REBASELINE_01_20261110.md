## 2. 精确计价合同（以分为货币精度；最终取整策略待单测冻结）

定义：
- `base_month_i`：仓位 i 所适用的基础月租；`factor(term)`：已确认租期对应折扣系数；`term`：1–60 整数月。
- `discounted_month_i = money_round(base_month_i × factor(term))`。
- `rent_total = Σ(discounted_month_i × term)`；`rent_monthly_after_term = Σ(discounted_month_i)`。
- `deposit = rent_monthly_after_term`（同一张订单，不按仓位再加管理费）；`management_fee = ¥50`。
- `coupon_discount` 在适用条件成立时从整期租金抵扣；`payable = rent_total − coupon_discount + deposit + 50`。
- 搬运权益在订单上独立留存资格与服务内容；与租期折扣、优惠券并存，除非另有批准规则，不改变押金和仓位租金计算。
- 组合仓整期租金按每个仓位分别计算再累加；押金等价于**组合折后月均**。在金额精度冻结前，严禁让组合仓出现“先各仓四舍五入再相加”和“合计后四舍五入”两套不一致结果。

**解释性边界**：此处将“折后月均”解释为租期折扣后的月均，订单级优惠券为一次性抵扣、不反算押金；若经营有“优惠券也计入押金基准”的政策，需单独追加裁定。当前代码并未完整遵循上述月租先算、整期再乘的算式，必须标差异而不是声称通过。

## 3. 价格展示与推荐合同

1. **公开态**：按店计算可租仓位的最低 `(有效公开月租 / 容量m³)`，显示 `¥X/m³/月起`。最低价所依赖的折扣/租期适用条件必须在数据层可追溯；不能把已售罄商品的低价作为门店可租起价。当前样例按12个月预置，不能自动宣称是全期限最低。
2. **携需求态**：先按 `capacity`、城市/区域、可售状态找候选，选择具体仓位或同店组合仓，输出选中方案的折后月租、整期租金、押金、券及权益。未选中有效仓位，不展示可支付的“正式报价”。
3. **排序主干**：有可售匹配方案优先；在符合容量及服务硬约束的候选中距离优先。低价是合法候选之间的辅助比较，不得使售罄店或容量不足仓位排在可租符合项之前。
4. 首页第三位运营卡、S01第三位考拉E存仍作为不同展示逻辑的服务/运营位；E存不伪装实物仓位、不纳入可直接下单库存。
5. 演示环境允许稳定虚构距离/服务时段，但数据来源必须内部分层；没有可靠位置授权时，不对外宣称“实际距离您 X 公里”的经纬度准确性。
6. 第二卡若非实际更便宜，不得仍显示绝对承诺“区域低价”；需要根据实际差价决定标签。

## 4. 线索与顾问

- 预约用仓：`phone`、`storage_address` 必填，完成基本格式校验后生成预约线索并提供可跟进回执；需有 CRM/销售跟进路径。仅存在浏览器本地存储时不得宣称已提交销售系统。
- 顾问咨询：仍是辅助咨询，联系人信息按现有咨询规则处理，不替代预约且不建订单；达到阈值后可增强视觉呈现，但不弹出强制拦截。
- 企业：与个人同商品、库存、基础价格、服务及正式下单守卫；企业表单按独立线索类型统计，不单设虚假的可用库存。
- 顾问阈值：当前候选实现为`整期租金 > ¥2,000`或`需求容量 > 10m³`，本轮保持当前边界，不自行更改比较符；若运营另有已批准新阈值，需通过决策记录更新。
