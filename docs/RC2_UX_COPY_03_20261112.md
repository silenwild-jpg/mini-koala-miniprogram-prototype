## 源码审计发现（已核实，页面实测按本PR Actions核验）

1. `app.js` 的遗留 `RESULT` 是可通过`page=RESULT`直达的页面；若无订单也无预约记录，原 `renderResult()` 默认直接输出“预约需求已模拟提交”，**错误表示用户已完成操作**。
2. 若存在订单，原RESULT含两个动作“模拟支付成功/失败”，它们通过 `handlers.paySuccess/payFailed`直接变更中心状态。当前主流程已使用BR04/O01付款弹层，不能让遗留状态页提供第二套支付控制。
3. 历史 `modal==='phone'` 中“手机号授权演示”与真实主入口采用的 `phone-auth.js` 不同，当前BR04订单入口需要微信/短信验证，公示S01/S02起价无需授权；不以源码存在证明旧弹层在正常消费者链路可见。
4. `br04/bridge.js` 的O01 `data-legal`点击仅展示“内部模拟条款说明，不签署正式协议”，**不能当作真实法律协议可读且有效**。本轮仅截图与记录HOLD，不编造协议全文、不改变同意勾选条件。

## 本次唯一产品源码定向修复

`demo/app.js` 的 `renderResult()` 改为**只读状态渲染**，不增删页面、底栏、边框、CTA容器或视觉母版：
- 无匹配记录：显示“暂无可查看的提交记录”，不伪称提交成功。
- 有 `leads[]` 且当前为预约结果：显示“用仓需求已保存；资料已保存在本机，尚未发送给顾问。”
- 有订单：从原 `orders[]`读取 pending、paid_simulated、payment_failed、cancelled、expired 等状态，显示“订单待支付／付款流程已记录／支付未完成／支付已取消／订单已过期”，非真实扣款仍保留必要说明。
- 移除RESULT内直接改变支付结果的两个按钮，保留“查看订单详情”和“继续浏览门店”，付款改回O01/M01既有流程。
- 不修改 `demo-core.js`、`br04/bridge.js`、`phone-auth.js` 的实际订单/支付/短信/协议执行逻辑。
