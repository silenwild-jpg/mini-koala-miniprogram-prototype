# PROTO-VIS-EXEC-01｜高保真视觉实施与双门禁规范
生效候选：2026-11-03；适用页面：H01、CAP、按物品估算、S01、S02、S5、O01、预约/快捷下单及公共浮层。
状态：用户明确要求建立执行机制。本文件进入治理 PR 后为候选；**合并到受控基线且关联门禁运行成功，才算仓库正式生效**。

## 一、唯一可信运行基线
1. 每次实施必须有 **基线 Commit SHA + 活动入口文件 + 页面渲染文件 + 对应构建产物 + 部署 ID**。无法追溯部署的 Netlify 手动上传文件，只能作为外部运行参考，不能认作 Git 分支的已归并结果。
2. 先确认实际路由：例如中央 S02 活动页为 `app/prototype/parallel/core-journey-fix-01/demo/app.js`，不能将旧独立 HTML 的 PASS 冒充中央页签收。
3. 允许演示数据补齐真实用户体验，但必须稳定、同源、可复现；不可用不可靠库存声称“仅剩 1 间”等实时稀缺性。模拟/真实数据来源应放入审计记录，不向用户界面添加解释性技术文案。
4. 如无法核对已批准视觉原图 SHA256，不得宣称“逐像素一致”“最终视觉通过”。

## 二、获批视觉优先级
| 优先级 | 依据 | 使用方式 |
|---|---|---|
| 1 | 最新用户明确批准的截图/结构决策 | 高保真约束，不得擅自替换布局、操作或文案 |
| 2 | 已冻结原图及可核对 SHA256 | 同状态、同尺寸比对 |
| 3 | 同期获批 PRD 与状态契约 | 决定展示条件和业务可用性 |
| 4 | 当前可运行中央页面 | 只作为实施起点，不得因其现状否定更新批准 |
| 5 | 历史 ZIP、旧 HTML、旧 CSS | 仅用于追溯，不得默认为视觉母版 |

## 三、变更边界
- **还原型**：有获批原图或明确结构时，仅实现必要响应式与数据接线。禁止自行增设 CTA、说明、卡片、阴影、装饰边框、图标矩阵和额外背景。
- **结构补足型**：已批准交互但无原图，只在当前视觉体系中定向增加；变更前提交区块层级、交互语义和边界说明。
- **探索型**：未批准的功能或设计先隔离为候选，不得归并视觉冻结页。
- 全站遵守 UI 文案减噪：一个概念仅表达一次，必要的容量不足、价格/库存条件、支付、隐私、安全提示不得为了减噪而删除。
- 375×812、390×844、实际滚动位置与六类业务状态均需校验。**浏览器正常不等于视觉正确**。

## 四、S02 已确认结构契约（2026-11-03）
`门店实拍（左下存取时间） → 热门仓型横幅（按适用状态） → 门店名/地址/导航 → 需求摘要或轻量估算 → [可选仓位 | 服务设施 | 交通路线] 单层等宽选项卡 → 当前选项内容`。
- 三个选项卡位于**同一层级**，内容互斥，默认“可选仓位”。
- 热门横幅最大程度还原用户标注截图的**真实 UI 部分**：白色融合式底、火焰、两行紧凑文字和右侧紧迫提示；红色圈画边框只是标注，不是 UI。**禁止“查看仓位”额外按钮**。
- 交通路线在选中态显示大幅地图、四种方式及导航；不叠放于仓位列表后面。
- 无有效需求时保留轻量估算入口，不阻断浏览；携带需求时显示摘要与修改。
- 单仓直接至 O01，不经 U01；不足容量的仓位不可当成满足需求的选项；组合仓明确“多个独立仓位”；不可用/售罄允许转其他门店。
- 真实或用户授权补齐的存取时间仅允许 `24小时`、`09:00-21:00`、`08:00-23:00`，每个门店固定，S01/S02 不矛盾。
- 顾问入口按高价值/大容量需要展示，不新增与现有主按钮重复的顾问卡。

## 五、双门禁
**G-TECH（可自动判定）**：PR 基线及文件差异、语法、中央路由、三选项卡契约、横幅禁止附加 CTA、必要交互状态、375/390 浏览器回归、跨页 ID/报价门禁。
**G-VIS（不可由 CI 冒充）**：获批原图 SHA、同状态视觉并排图、顶/中/底内部滚动截图、信息密度、母版结构、文字与真实按钮数量、历史 CSS 影响、审批人签收。

只有 **G-TECH PASS + G-VIS 人工 PASS + 同源部署可追踪** 才能标记“已冻结/已归并/已发布”。
CI 的技术 PASS 绝不自动把 G-VIS 标记为 PASS。

## 六、各类状态必须区分
`APPROVED`（设计获批）→ `IMPLEMENTED`（代码已产出）→ `TESTED`（实测）→ `VIS_SIGNED`（原图签收）→ `MERGED`（主线归并）→ `DEPLOYED`（可追踪部署）。任何环节缺证据不得越级。

## 七、拒绝归并条件
缺少原图文件但宣称终签；对已冻结结构擅自重排；新增未经批准的 CTA；用旧独立 HTML 的截图证明中央页面；仅因工作流绿色即宣称视觉 PASS；Netlify 手动部署无法证明源码关联；未经批准跨页扩散样式或组合仓错误表达。

## 八、执行模板
每次 PR 填写 `.github/pull_request_template.md`，并使用 `docs/visual-evidence/README.md` 的核对表及证据记录。机器检查在 `scripts/check_proto_vis_exec_01.cjs`；对视觉修改生成 `visual-guard-report.json`。必要时先留在 Draft/HOLD，不能以“继续”指令推断可以自行合并或发布。
